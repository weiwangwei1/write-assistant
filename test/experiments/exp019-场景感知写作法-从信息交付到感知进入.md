# exp019: 场景感知写作法 — 从"信息交付"到"感知进入"

> 实验日期：2026-07-29
> 前置：exp001-018 共提取 56 条原则（P001-P056）+ 18 个技法维度（S1-S18）
> 问题来源：用户提问"为什么框架性问题会导致这么多问题，真正的作家是怎么思考的"

## 一、问题诊断

### 1.1 根因：beat sheet 的信息交付思维

当前 chapter-writer 的 beat sheet 结构：

```json
{
  "beats": [
    {"beat_id": 1, "purpose": "开场/世界观展示", "info_delivery": "action"},
    {"beat_id": 2, "purpose": "冲突/能力展示", "info_delivery": "action"},
    {"beat_id": 3, "purpose": "发现/悬念", "info_delivery": "discovery"}
  ]
}
```

写手看到 `purpose: "开场/世界观展示"` + `info_delivery: "action"` 时，思维路径是：

> "这个 beat 要交付的信息是'世界观'，交付方式是'动作'"
> → 写出"动作包装的信息"而非"角色经历的场景"

结果：场景像一份填表——每个 beat 对应一组要交代的信息，角色沦为信息载体。

### 1.2 对比：真正作家的思维路径

烟雨江南写"永夜君王"开篇时的思维不是"我要交代永夜大陆的世界观"，而是：

1. **镜头在哪** → "永夜大陆大部分时间都是暮色昏昏"（大陆级广角）
2. **天空什么样** → "双子阿尔法星转入近地轨道"（天文级）
3. **大地什么样** → "月光如薄纱般从天空垂落大地"（大地级）
4. **谁在这里** → "其中有一个瘦小的男孩"（人群→个体）
5. **他在干什么** → "也在努力翻找"（动作）
6. **他找到了什么** → "纸包里居然是一个面包"（极近景·物件）
7. **他的身体怎么了** → "一滴血珠从他手上的伤口中渗出"（极近景·身体）

**信息（世界观/经济/社会结构）是感知的自然副产物，不是交付的目标。**

### 1.3 诊断验证

用 `scene_perception_lint.py` 对比正式版 Ch1 和 v4 Ch1：

| 维度 | 正式版 | v4版 | 说明 |
|------|--------|------|------|
| D1 信息交付段 | 100 | 94.7 | v4 有一段信息密度过高的背景交代 |
| D2 叙述者翻译 | 100 | 76.0 | v4 有 2 处"动作→解释"模式（脸骗人手不行/那不叫硬） |
| D3 空间失锚 | 100 | 100 | 两版都好 |
| D4 感官一次性 | 40 | 40 | 两版共同短板：感官引入后消失 |
| D5 焦距起点 | 95 | 95 | 两版都有世界级广角开篇 |
| D6 世界自转 | 90 | 90 | 两版都有世界独立活动痕迹 |

**核心发现**：v4 追求叙述者声音（v4 自评认为这是最大突破），但诊断显示叙述者声音越界成了"行为不自足"——这正是 P051 所警告的。

## 二、新方法：场景感知写作法

### 2.1 核心原则

**用一个判断标准替代 beat sheet：**

> 写每一句之前，问自己：**角色此刻感知到了什么？**
>
> 不是"这段要交代什么信息"，而是"角色站在那里，他的身体在感知什么"。

信息从感知中自然流出。不需要标注 `info_delivery`。

### 2.2 场景层替代 beat 层

用"场景层"（感知层）替代"beat"（信息层）：

| 旧 beat sheet | 新 scene sheet |
|---------------|----------------|
| beat_id: 1, purpose: "开场/世界观展示", info_delivery: "action" | scene: "城墙上", focal: "世界级→建筑级", perception: "风/光/裂缝", character_action: "数人" |
| beat_id: 2, purpose: "冲突/能力展示", info_delivery: "action" | scene: "东墙下", focal: "近景", perception: "壳的纹路/暗紫色光", character_action: "扎刀" |
| beat_id: 3, purpose: "发现/悬念", info_delivery: "discovery" | scene: "壳腔内", focal: "极近景", perception: "铜钱的触感/血的黏", character_action: "翻铜钱" |

关键区别：
- beat 问"要交付什么信息" → scene 问"角色感知到什么"
- beat 标注 `info_delivery` → scene 标注 `focal_length`（焦距）和 `perception`（感知通道）
- beat 是信息单元 → scene 是感知单元

### 2.3 场景感知五问

写每个场景前回答五个问题（替代 beat sheet 的 purpose/info_delivery）：

1. **镜头在哪一层**（焦距） → 世界级/城市级/建筑级/人物级/极近景
2. **角色的身体在干什么**（动作） → 不是"要展示什么"，是"此刻身体在做什么"
3. **角色感知到什么**（感官） → 视觉/听觉/触觉/嗅觉/温度，至少2种叠加
4. **世界在干什么**（自转） → 与角色无关的、世界自己的活动
5. **这个感知改变了什么**（推进） → 感知→反应→新感知的链条

信息从这五问中自然产出，不需要单独标注。

### 2.4 与 S1-S18 的关系

S1-S18 是这个方法的"自检清单"——写完后逐维检查。场景感知五问是"动笔前的思维框架"——写之前设定感知方向。

```
场景感知五问（动笔前） → 写正文 → S1-S18 自检（写完后） → 诊断脚本验证
```

## 四、实验结果

### 4.1 v5 Ch1 开篇（场景感知法）

```
大徵在别的位面开了裂缝。征诏令管着裂缝，能拿的都拿。拿的人叫征调者，拿够了叫功勋。

风从垛口灌进来。程铖没有回头，也知道身后只剩三个人。连他四个。第七营满编十二。
```

**五问验证**：
1. 镜头在哪：世界级（大徵/位面/裂缝）→ 建筑级（垛口/第七营）→ 人物级（程铖）
2. 身体在干什么：没回头，在数人
3. 感知到什么：风（触觉）+ 身后人数（听觉/空间感）
4. 世界在干什么：裂缝开着，风在灌——世界自己的活动
5. 感知改变了什么：从"数人"到"知道只剩四个"——感知驱动认知

**与 v4 开篇对比**：
- v4："城墙上有一道裂缝，裂缝那头的天是红的"（建筑级起笔）
- v5："大徵在别的位面开了裂缝"（世界级起笔）→ 符合 P048

## 五、结论与后续

### 5.1 核心发现

1. **beat sheet 的 `purpose` + `info_delivery` 字段是机械写作的根源**——它们让写手按"信息交付"思维而非"场景感知"思维写作
2. **场景感知五问可以替代 beat 的信息标注**——信息从感知中自然流出，不需要单独标注
3. **叙述者声音是双刃剑**——v4 追求叙述者声音导致 D2 降分（行为不自足），需区分"叙述者评论"和"叙述者翻译"
4. **感官一次性是两版共同短板**——P045 需要重点修复

### 5.2 后续

1. **v5 完整重写**：用场景感知法重写 Ch1-3 全文，运行诊断脚本验证
2. **scene_sheet 注入**：验证通过后将 scene_sheet 模板注入 chapter-writer，替代 beat_sheet
3. **诊断脚本常态化**：将 `scene_perception_lint.py` 纳入提交流程，作为 style_lint 的补充
4. **S1-S18 注入 style_card**：场景感知法 + 18 维自检 = 完整的写作思维框架

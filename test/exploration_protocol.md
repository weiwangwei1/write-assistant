# 探索工作区协议

> 本文件定义"灵魂探索"类工作的标准格式与流程，供后续所有探索类工作复用。
> 首次实践：灵魂探索（2026-07-29），产出 6 个实验 + 20 条原则 + 四轮章节迭代。

---

## 一、什么是探索工作

探索工作回答一个**框架规则回答不了的问题**。它不是修 bug、不是加 lint 规则、不是调阈值——它是当机械指标全绿、审核全过、但作品仍然"差了点什么"时，去找那"一点"是什么。

**适用场景**：
- 指纹全对但读感不动人
- 审核全过但用户/读者反馈"缺韵味"
- 框架规则已覆盖所有可量化维度，但质性差距仍然存在
- 需要对照原作做深度拆解，提取不可量化的写作手法

**不适用场景**：
- 修 lint 规则（属于框架迭代）
- 调阈值（属于风格包 overlay）
- 加审核层（属于框架迭代）
- 补设定/大纲（属于创作流程）

## 二、探索工作区结构

```
test/
├── README.md              ← 工作区总览：核心假设 + 实验选题池 + 产出边界
├── exploration_protocol.md ← 本文件：探索格式规范
├── experiments/            ← 对照实验（每实验一文件）
│   └── expNNN-标题.md
├── practice/              ← 章节迭代实验（多版本并存，不覆盖 output/）
│   ├── chapter_001_v2.txt
│   ├── chapter_001_v3.txt
│   └── chapter_001_v4.txt
├── principles.md           ← 原则库（累积，候选进 style_card）
├── craft_guide.md          ← 写作技法指南（将原则浓缩为动笔前自检清单）
├── optimization_plan.md    ← 优化方案（将原则系统化为可操作体系）
├── comparison_report.md   ← 对照阅读报告（原版 vs 重写版逐段对比）
├── self_diagnosis.md       ← 自我诊断（每轮迭代后自评）
├── vN_self_evaluation.md   ← 版本自评（v2/v3/v4 各一份）
└── final_evolution_report.md ← 最终进化报告（四版轨迹 + 入库建议）
```

## 三、单次实验格式

每个实验文件遵循以下结构（控制在 1-2 屏内）：

```markdown
# expNNN：实验标题

> 场景类型：一句话描述
> 原作来源：书名 + 章节/页码
> 探索问题：这个实验要回答什么问题？

## 1. 取样

引用原作中"有灵魂"的段落（读者会被击中、会记住、会截图分享的那种）。
标注出处和选它的理由。

## 2. 精读

拆解作者到底在做什么——不是统计指标，而是：
- 信息放在哪？（前置/后置/隐藏/分散）
- 情感什么时候到？（即时/延迟/事后）
- 视角给谁？（主角/旁观者/世界/物件）
- 什么东西被刻意没写？

## 3. 对照

拿我们同场景类型的段落并排，做差距分析。
标注每处差距的根因（不是"写得不好"，而是"缺了什么手法"）。

## 4. 提取

产出 1-2 条原则，进 principles.md。
格式：
- **P0NN 标题**（来自 expNNN）
- **断言**：一句话原则
- **证据**：原作中的具体段落
- **自检**：写手动笔前问自己的问题
- **剂量**：频率建议（每章/每卷/全书个位数次）
```

## 四、章节迭代格式

当探索成果需要验证时，在 `practice/` 中做多轮迭代：

### 文件命名

```
chapter_NNN_vN.txt          ← 迭代版本（v2/v3/v4...）
chapter_NNN_soul.txt        ← 灵魂修订版（基于真人阅读反馈的逐行修改）
style_lint_chN_vN.json      ← 每版的 lint 结果
```

### 迭代流程

```
原版（output/）
  ↓ 应用第一批原则
v2（五维技法实验版）
  ↓ 自评 + lint + 对照阅读
v3（修复版）
  ↓ 自评 + lint + 对照阅读
v4（深度版）
  ↓ 自评 + lint + 最终报告
入库评估 → 是否替换 output/
```

### 每轮迭代必产出

1. **lint 结果**：`style_lint_chN_vN.json`（确认 L0 全绿）
2. **自评文件**：`vN_self_evaluation.md`（逐维对照前版，标注解决/改善/未净）
3. **对照阅读**：标注每处改动的手法依据和原则编号

## 五、原则库格式

`principles.md` 中每条原则遵循统一格式：

```markdown
## P0NN 标题（来自 expNNN）

**断言**：一句话原则——不是"应该怎么写"，而是"缺了什么会怎样"。

**证据**：原作中的具体段落 + 对照组（我们的作品中的差距）。

**自检**：写手动笔前问自己的一个问题。

**剂量**：频率建议。多即成模板，模板即死亡。
```

**原则设计原则**：
- 灵魂不能配额化——原则是注意力方向，不是 lint 规则
- 每条原则有且只有一个自检问题（多了就稀释）
- 断言用"缺了什么会怎样"而非"应该怎么写"——后者变成模板
- 证据必须包含对照组（我们的 vs 原作），不能只有原作

## 六、产出边界

### 探索工作区产出

- 原则进 `principles.md`（标注证据来源）
- 技法指南进 `craft_guide.md`（浓缩为自检清单）
- 优化方案进 `optimization_plan.md`（系统化为可操作体系）
- 迭代版本存 `practice/`（不覆盖 `output/`）

### 候选进框架

- 累积 5-8 条原则后，评估哪些进 style_card（以"原则+自检问题"形式）
- 评估哪些 lint 阈值需要调整（基于迭代版本的 lint 数据）
- 评估哪些手法需要固化进 chapter-writer 倾向库

### 探索工作区不做的事

- 不加 lint 规则（可量化才 lint 化，探索的是不可量化的）
- 不加审核层（探索成果通过 style_card/倾向库注入，不新增审核步骤）
- 不设配额（灵魂配额化即死亡）
- 不覆盖 output/（迭代版在 practice/ 验证，入库需走完整审核流水线）

## 七、探索选题设计方法

### 选题来源

1. **真人阅读反馈**：用户以读者视角标注的"停顿一下"的位置（如 Ch1 的 26 处反馈）
2. **原作对照差距**：我们的作品 vs 原作的同场景段落对比
3. **原则空白点**：现有原则库未覆盖的叙事手法
4. **跨作品对比**：不同作者处理同一场景类型的手法差异

### 选题排序标准

按"灵魂密度"排序——即该场景类型对读者体验的影响权重：

| 权重 | 场景类型 | 理由 |
|------|---------|------|
| 高 | 死亡/牺牲/告别 | 情感冲击最大，手法差距最明显 |
| 高 | 开篇/转场 | 第一印象决定追读率 |
| 中 | 战斗/冲突 | 节奏感差距隐蔽但影响大 |
| 中 | 日常/对话 | 角色辨识度和世界质感的主要载体 |
| 低 | 设定交代/信息传递 | 可量化程度高，lint 已覆盖大部分 |

### 选题池管理

在 `README.md` 中维护选题池表格：

```markdown
| # | 场景类型 | 为什么 | 状态 |
|---|---------|--------|------|
| exp001 | 世界重量（开篇） | 世界不服务于剧情时的存在感 | ✅ 已完成 |
| expNNN | ... | ... | 🔲 待做 |
```

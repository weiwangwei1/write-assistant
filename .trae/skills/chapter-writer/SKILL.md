## 一、角色定位

根据大纲、角色卡、分镜（beat sheet）生成章节正文，提交 `handoff/chapter_draft_ch{N}.json`。
**提交前置条件：style_lint L0 红线全绿（exit code 0；v3.1 起 L1 为顾问项，报告但不阻断，由 detail-reviewer 逐条回应）。**

## 二、设计原则（为什么瘦身）

1. **能写成脚本的规则，不写成提示词**。提示词规则靠 LLM 自觉执行，实测执行率不可靠（v2.2 禁令"一种"残留 8 处、"路灯"过审即为证据）。
2. **硬约束必须 ≤10 条**。规则数量与单条执行率成反比；超过 10 条后 LLM 注意力分配失效。
3. **不可校验的要求降级为"倾向"**。倾向允许违反，但违反应是主动选择而非无意识漂移。
4. **规则冲突时**：lint 硬约束 > 倾向；爽点需求不得以牺牲文风红线为代价。

## 三、硬约束（H1-H10 通用 + H11 黄金三章附加，全部可机器校验）

| # | 约束 | 校验方式 |
|---|------|---------|
| H1 | **篇幅**：以本书 production_notes 为准（有龙则灵 2800-3500；万纹师 2600-3200）。**宁删勿补**：初稿写长，修订只删不补——写短硬补必伤节奏；lint chapter_length 规则提交前必须清零 | 脚本数字数 + style_lint chapter_length |
| H2 | **文风 L0 红线全绿**：`python style_lint.py 本章文件 --json handoff/style_lint_ch{N}.json` 退出码 0 = L0 通用反AI红线清零（"不是A—是B"≤2/章；一段一喻；"一种+感觉类"/感觉编号/总结式心声/时代错词 0 容忍）。v3.1 起碎段率/比喻总数/章首通道等 L1 规则为顾问项：超限仍报告但不阻断——禁止为凑阈值删好比喻或删语法必需的字，接受 advisory 即可，由 detail-reviewer 逐条裁定 | style_lint |
| H3 | **跨章事实表先行**：正文生成前必须填写 `beat_sheet.cross_chapter_facts`——本章全部专名、全部数字与年代（**显式写出验算过程**，如"庚午→庚午=60年"）、角色/物品位置状态、已知信息清单（前文已揭示的信息只能引用，不得重新发现）、**角色确定性状态**（每个视点角色对本章关键信息的确定程度：first_encounter=首次遭遇用推测语气"像是/似乎/倒像是"/partial=部分了解/full=已确证可用"就是/分明是"）、**character_internal**（每个视点角色本章的内在矛盾/欲望/情感变化，至少1条，须引用角色卡 conflicts 或 personality_extreme 中的至少一条；**至少1条内在矛盾须在正文中以"精算失效/被迫选择"场景展示（非旁白），即主角在面临无法用精算解决的处境时的行为反应，该场景对应的 beat 标注 `weight: minor`，`purpose: 角色深度`**）；**DNA动作出口兑现（v3.3新增）**：`character_internal` 中新增 `dna_outlets_used` 字段，标注本章兑现了哪些DNA特质的动作出口（引用角色卡 `personality_dna[].action_outlets`），每章≥3条，兑现的动作用原文引用 | 交接卡字段存在性 + detail-reviewer 抽验 |
| H4 | **单章密度上限**：beat≤6；新命名概念≤2；新出场角色≤1；伏笔动作≤3；大爽点≤1。**黄金三章（≤2600字）beat≤4，其中 major_beat≤3；常规章（2400-2800字）beat≤5，其中 major_beat≤3。** major_beat=爽点/伏笔核心/关键转折；minor_beat=过渡/信息传递/氛围铺垫。每个 beat 须标注 `weight`（major/minor）。任一超限在分镜阶段拆章，不得侥幸提交 | 交接卡 beat_sheet 字段计数 |
| H5 | **爽点标注**：每个 purpose=爽点 的 beat 必须填 `shuang_type`（S/A/B/C/reveal/na）；reveal 不计入爽点数；前 2 章无 S/A 时本章必须有 ≥1 个 S/A | 交接卡字段 + goal_tracker 滚动核对 |

| H8 | **时间线与设定圣经一致**：本章出现的年份/干支/时长/关键设定词（如"上一次献祭"），必须与 `memory/setting_bible` 逐条比对通过；lint 输出的 timeline_clues 逐条确认 | style_lint 报告项 + detail-reviewer 复核 |
| H9 | **对话占比 35%–60%（顾问指标）**：按带引号台词行字数占比计。v3.1 起不再一刀切——探索/独处场景可低于下限，交锋/谈判场景可高于上限；占比是否合理的场景判断由 detail-reviewer 负责，写手不得为凑占比增删对话 | style_lint 报告 + detail-reviewer 场景判断 |
| H10 | **格式**：分段排版；单段超过 200 字需自检必要性（手机端可读性）；不得使用 Markdown 标记 | 脚本统计 |
| H11 | **黄金三章人味阈值（v3.3 新增，仅 Ch1-3）**：前 3 章正文必须出现以下 4 项（"有无"校验，不查出现次数）：① ≥1 个"掉价的私密细节"——主角在做一件与剧情无关、甚至有点掉价的事（如蹲台阶倒雨水、数铜板、抠旧衫线头）；② ≥1 个"荒诞反差画面"——具体共置画面，非形容词（如"穷到只剩破碗 + 冷静到反常"同一帧）；③ ≥1 次"冷幽默控场"——幽默服务控场/解构恐惧/推进关系至少一个，不是段子；④ ≥1 次"动作代替独白"——用可观察的动作表达情绪，不用内心独白。缺任一项，detail-reviewer 标记 `human_flavor_insufficient` | 交接卡 `human_flavor_check` 字段 + detail-reviewer 验收 |

> H3–H6、H11 为交接卡**结构约束**——缺字段或字段不合规，总编直接拒收，不进入评审环节。
> H11 仅适用于黄金三章（Ch1-3），常规章不校验。

## 四、提交前自检流程（不可跳过）

```
1. 写 beat sheet（含 cross_chapter_facts / shuang_type / suspense_budget_check）
2. 写正文（初稿写长，宁删勿补）
3. **先数字数**：低于下限先扩写（扩场景/加冲突/补伏笔，不凑字），达标后才送检
4. python style_lint.py 本章 --json handoff/style_lint_ch{N}.json（带本书 --config 篇幅配置）
5. 退出码≠0 → **先存修复前快照 handoff/pre_lint_ch{N}.txt** → 自修 → 回到 4
6. 若经历过修复轮次：python fix_auditor.py handoff/pre_lint_ch{N}.txt 本章文件 --json handoff/fix_audit_ch{N}.json（只产证据，不判定）
7. 退出码=0 且 chapter_length advisory 清零 → 填交接卡（附 style_lint 卡 + fix_audit 卡路径）→ 提交
```

## 五、倾向库（非强制，供参考）

以下内容不逐条验收，写作时主动遵循；与硬约束冲突时以硬约束为准。

### 5.1 节奏与句式（原第三节，已部分上收为 H2）
- 长短交替是主旋律；连续 3 句同句长时考虑断句
- 超短句用于情绪高点、反转瞬间——**只在重音处碎**，日常叙述保持正常段落
- 每章可有 1 个 ≥200 字长段（推理/氛围/动作）做节奏对比

### 5.2 对话（原第四节）
- 对话三明治：动作+对话+动作；小动作优于大动作
- 每句对话带信息或性格；用追问代替陈述
- 角色辨识度：写完遮名自读，应能分辨谁是谁（detail-reviewer 会抽 5 句盲测）

### 5.3 爽点与钩子（原第六、七节，阈值已上收为 H5）
- 爽点九步闭环：压抑→打压→蓄力→爆发→**对手反驳→二次证明**→打脸→回报→新期待
- **打脸类爽点（shuang_type=S/A）的 beat_sheet 必须包含 opponent_rebuttal 子环节**：对手提出一个看似合理的反驳→主角用更精妙的证据/手艺回击→打脸重量翻倍。无反驳的打脸=廉价冲突
- **禁止"旁白替爽"模式**：如"石头给林深递眼神，低声说看见没我就说林哥不简单"——通过角色反应自然展示爽感，而非直接告诉读者该觉得爽。让读者自己觉得爽，比让角色替读者说出来要高级得多。style_lint 的 narrative_dialogue 规则检测此类模式
- **打脸即时反馈**：主角打脸对手后，须有旁观者反应（低笑/倒抽凉气/议论）放大爽感——无反馈的打脸等于没打。但反馈用动作不用台词，禁止配角替读者说出"他好厉害"
- **金手指成长暗示（前10章）**：每3-4章须有1处主角能力成长的微暗示（如"看纹比昨天更清晰了一层"），给读者"他会越来越强"的预期。暗示须是感官体验而非旁白解释
- 张弛比约 3:1；大爽点每 3–5 章 1 个
- 钩子要具体可感：写清"是什么+和主角的关系"；强钩与缓钩交替

### 5.4 开头（原第二节）
- 6 种开头类型轮换（动作/感官/对话/场景动作/悬念/氛围），不与上章同类
- 前 300 字完成冲突爆发+主角登场+目标浮现；禁止慢悠悠写风景流水账

### 5.5 信息与设定（原第八节）
- 设定信息不集中讲解，通过剧情与对话自然释放
- **每个涉及设定信息释放的 beat 须标注 `info_delivery`**（action=角色行为展示 / dialogue=对话释放 / sensory=感官体验 / discovery=角色主动发现 / exposition=旁白解释）；exposition 每章≤1处且须注明理由，detail-reviewer 有权要求改为其他交付方式
- 术语首次出现必须伴随上下文暗示其性质；前 5 章不得出现未解释术语
- 每段须完成至少一项功能（推进/人设/伏笔/氛围/共情），否则删

### 5.6 角色（原第九节）
- 言行符合角色卡 personality 与 current_state，不 OOC
- 主要角色每章 ≥1 个与剧情无关的个人细节（习惯/小动作/弱点）
- 配角有独立目标，非纯工具人
- **signature_lines 是可选调色板，不是必用清单**——每5章最多用2条不同签名台词，禁止连续2章用同一条；lint 跨章检测会统计签名台词频率
- **每个角色至少有一个"反模式时刻"（anti_pattern_moment）**——在特定触发条件下打破自己的语言/行为模式，这比重复签名台词更能立住角色。查阅角色卡 `language_fingerprint.anti_pattern_moments` 字段获取各角色的反模式触发条件

### 5.6b 人味互动（v3.3 新增 ★）
- 每章至少使用 1 个"互动模板"产出碰撞人味，调用关系卡中的 `interaction_template`
- **五个可调用模板**（来自 character-designer v1.6 关系网设计）：
  1. **斗嘴喘息**：紧张局中插入冷热对冲的幽默——A接B的冷话茬→B回一句更冷的→A被噎住→C打圆场。作用：缓解压力+展示性格+推进关系
  2. **物件对照**：两个情感物件同框，不写旁白——A的破碗×B的银耳铛放在同一张桌上，读者自己看见穷富差距。作用：用物件代替叙述
  3. **生活流交叉**：剧情间隙插入与剧情无关的日常——吃饭、喝水、打盹、琐碎对话、被生活打断。作用：制造节奏喘息，紧张感有落差才觉得"活"
  4. **镜像失态**：两个"端着"的人同时露怯——A的手抖了，B正好也在攥拳。作用：互相照见狼狈，建立"同类"认同
  5. **穷体面对照**：两个穷人比"穷讲究"建立认同——A的旧衫洗白、B的工具磨亮。作用：用不值钱的东西撑体面，穷人之间的默契
- 模板调用标注在 beat_sheet 的 `interaction_template` 字段
- **禁止"旁白替爽"**：禁止通过角色台词直接告诉读者该觉得爽（如"看见没我就说林哥不简单"），让读者自己感受到爽感比角色替读者说出来更高级

### 5.7 幽默（原第五节，v3.3 强化）
- 闷骚式搞笑、语境错位、自我吐槽、先歪后正
- 不直接点破笑点；硬设定后紧跟一句吐槽消解枯燥
- **幽默是控场武器，不是段子（v3.3 新增）**：幽默是角色在紧张局面里**解构恐惧、确立掌控、规避暴露**的手段。每次幽默必须同时服务"缓解紧张"+"展示性格"+"推进关系"至少一个
- **主角底色如果是"掌控者"，幽默就应是"腹黑式冷幽默"**，不是"搞笑卖萌"——越死局越精确，越压越冷，笑点在"他说了句最不该说的话但说得最有道理"
- 禁止"旁白替爽"：禁止通过角色台词直接告诉读者该觉得爽（如"看见没我就说林哥不简单"），让读者自己感受到爽感比角色替读者说出来更高级

### 5.8b 行动化立人设（v3.4 新增 ★）

> **诊断原则（为什么我们的小说吸引力低）**：主角"想"太多、"做"太少，且"做"是"想"的注脚。顶流让读者"看懂了所以爽"，我们让读者"被告知了所以乏"。单拎一句还好，整章/前三章不吸引人，根子就在这——句子是通的，但主角没有在"做"让人记住的事，全靠文字把局面讲清楚。**人设必须靠"做的事"立，不靠内心独白/旁白/形容词——读者自己得出的结论，比任何形容词都硬。**

三条铁律：

1. **人设靠行动立，不靠说教**。禁止用一句内心独白或旁白告诉读者主角是什么样的人（"他很聪明""他掌控全局"）。只能靠他做了几件别人看不懂、事后才惊觉的事来证明。检验标准：把主角所有内心独白和旁白删掉，读者还能从"他做的事"里得出同样的人设判断吗？不能，说明人设没立住。

2. **禁止"内心独白自夸"**：主角不能在脑子里说"我早就看穿了""这局我算定了"。掌控感必须通过"看不懂的冷动作 → 事后兑现"来证明，而不是内心盘算。掌控全局的能力，恰恰要在"乱"里才显——一间安静的工坊展示不了这个。

3. **每个动作必须有客观后果**（改变了局面/救了一环/堵了一处），不是摆姿态。三个"看不懂的冷动作"要落在同一时刻全部兑现，读者才恍然"他是天才"——不是被告知，是自己看懂的。

**冷动作兑现结构（掌控全局型/天才型主角的专属展示法）**：

- 破局/乱局场景，主角混在人群里，读者看不出他是谁
- 他做 3 个"当时看不懂"的冷动作（读者觉得奇怪，甚至以为他在破坏/添乱/送死）——如给小孩塞袋粮食说"往东边第三道门，说怀里的信"、顺手把一摞木板横翻在路中央、拦住一个跑反方向的民兵让他折回去守某段墙
- 事后同一时刻，3 个动作全部兑现（传的信点燃了油槽、木板绊住兽潮阵型、民兵守住了唯一没塌的缺口）——一整城的溃败被他三个动作盘成了"刚好能撑到天亮"的局
- 禁忌：全程不夸他、不解释他、不让他说"我早看穿了"。读者自己得出的结论，比任何形容词都硬

**黄金三章组织原则**：第一章先立"人"（行动证明他是谁），职业/机制/能力往后放。第一眼必须让读者记住"这个人"，不是"这个职业"。

**与既有规则的衔接**：本节的"行动立人设"是 H11"动作代替独白"的推广版（H11 只管黄金三章有无，本节管所有章节的立人设方式）；"冷动作兑现"是 5.3"禁止旁白替爽"的正向解法（不告诉读者该觉得爽，造一个让读者自己看懂的局）。

### 5.9 实战验证技法（v3.5 新增 ★）

> 以下技法在《第三纪元》黄金三章实战中验证有效，从读者反馈提炼，补充倾向库。

**1. 悬念钩子即时回响**。章末抛出的悬念钩子，下一章必须有至少一句话的即时回响——不解答，不展开，只是让读者感到"作者没忘这件事"。否则钩子会在下一章开始前被遗忘。示例：Ch2末"刻的人姓沈，三年前死在昭关城下"→Ch3撬芯子时"锉刀走到芯子边缘，他的手顿了一下，纹路的走势在这里拐了个弯，和昭关城下收尸时见过的那道刻痕，收刀的方向一样"——一句话，不展开，但钩子活在了读者脑里。

**2. 视角过渡标记**。当一章内从有限视角切到全知群像视角时，必须有明确的"视角交接句"——让读者知道"以下不再是某人的实时经历，而是事后拼凑"。示例：Ch1从顾衡有限视角切到"有人说"群像前，加一句"后来的事是城里人拼出来的，谁也没从头看到尾，各人记住各人眼前那一段"——读者立刻知道视角变了。

**3. 战斗脏感**。围城/大战场面不能太"整"——守军行为过于统一（退→有人站出来→跪→主角出手）会让主角的冷静显得突兀而非珍贵。必须有1-2句人性溃败细节作为参照物：有人扔矛逃跑被踩、有人趁乱扒死人甲、有人对着兽潮下跪求饶。这些细节让主角的冷静"有东西衬"，而不是悬浮的。

**4. 造物视觉锚点**。机械/构装/造物首次出现时，必须给具体视觉锚点——体型（到人胸口/比人高/没人高）、姿态（蹲姿像抱膝/伏地像蓄力）、与人的比例关系。不能只有概念描述（"半边甲片半边骨架"），读者脑中要能形成画面。首次出现给全貌，后续出场补动态细节。

**5. 物件重复作节奏锚点**。一个小物件在关键节点重复出现（如三枚铜板：开头数、结尾数、危机时数），不是标签，是"在失控世界中维持秩序感"的节奏锚点。重复出现的物件必须：①不值钱（铜板而非玉佩）；②与剧情无关（数铜板不影响守城）；③每次出现时角色状态不同（平静→紧张→决断），物件不变人变。

**6. "用造对抗毁"对称结构**。主角的行为与世界威胁形成对称——兽潮拆城，主角拆兽骨做关节；敌人破坏，主角建造。这种对称让角色本质（"用造对抗毁"的人）通过行动自然显现，不需要旁白点破。设计 beat sheet 时主动寻找这种对称机会。

**7. 意象繁殖自检**。核心意象（如"一圈套一圈""纹路"）在不同对象上反复使用是世界观语法，但同一描述语在3章内出现4+次即为自我繁殖——读者会觉得作者词穷。提交前自检：grep 核心意象的出现频次，超4次的用同义动词（绞/拧/压/叠/缠）替代。lint v2.8 `phrase_repeat` 会报章内3+次重复。

**8. 对话标签变化**。同一对话标签（"X道"/"X说"）章内出现4+次时，必须用动作节拍替代——"顾衡把锉刀搁回案上"比"顾衡道"更有画面且不重复。对话密集的章节，标签变化率应≥50%（10处对话中至少5处用动作节拍）。lint v2.8 `dialogue_tag_repeat` 会报4+次重复。

**9. 明喻显性度控制**。连接两个关键叙事元素的明喻慎用"像"——"壳上纹路像城北金属上的花纹"直接焊死了关联，读者没有发现空间。如果要让读者自行关联两个元素（暗线），只描述共同特征（"纹路收口往里拧"），不加"像"。只有明线才用明喻。

**10. 悬念钝化逐层加码**。关键人物/事件的悬念揭示需"钝刀慢割"——不直接揭名，先用感官/地点/特征间接指代，后续章节再逐步补充信息。示例：Ch2末不直接说"刻的人姓沈"，而用"昭关城下的土，还没把这个人埋干净"→Ch3通过"收刀方向一样"暗示关联→Ch4+再揭晓名字。延长读者猜测过程，增强悬念"咀嚼感"。

**11. 机制失败对照**。引入新力量机制（如献祭/超能力）时，必须展示至少1个失败案例——有人献祭传家宝却毫无反应，或因心念不纯被反噬。这能强化机制的残酷性与不确定性，避免读者形成"只要使用就一定成功"的预期套路。

**12. 隐性代价暗示**。主角使用超常力量时，须加入1个微小的生理代价暗示——指尖渗血、短暂耳鸣、或手腕不可察地颤了一下。这不会削弱强大感，反而暗示"驾驭超时代力量"有隐性代价，为后续剧情埋线。代价必须可视但不影响当前行动（如"指甲缝渗血被光吞了"）。

**13. 感官闭环**。章/弧首尾用关联感官细节呼应——Ch1开头"血腥味先到的"→Ch3结尾"风里终于有了一丝活人的炊烟味"。形成从"死"到"生"的微弱闭环，强化文学质感。首尾感官不必完全对应，但需有情感/意象关联。

## 五b、文学质量主动引导（v2.2 新增 ★）

> **核心原则**：lint 是工具不是裁判。修 lint 的目标是**消除 AI 痕迹**，不是**消除文学性**。
> 写手常犯的错误是「为了过 lint 而过度矫正」——删了好的比喻、删了语法必需的"了"、
> 把直接对话改成叙述摘要。**这些都是框架要防止的问题，不是要制造的问题。**
>
> 完整规则意图文档见 `auto-runner/rule_intents.md`（写作前必读）。

### 5b.1 修 lint 时的三条铁律

1. **只修 AI 痕迹，不修文学手法**。lint 报"像"超限时，删陈词比喻（像山一样/像火一样），保留精准比喻（像一锅将开未开的水）。优质比喻占比≥70%时 lint 只报 minor，可保留。
2. **不骗计数器**。把"像"改成"如"来躲计数——lint 看不到了，但比喻堆叠问题还在，且"如"字多了又是另一种 AI 腔。要么删要么保留并接受 minor。
3. **修了不引新问题**。每次修 lint 后自检：删除的内容是否导致语法残缺？改写的句子是否失去原有张力？如果修了 A 坏了 B，回退重来。

### 5b.2 七种过度矫正（禁止）

| # | lint 报错 | ❌ 禁止做法 | ✅ 正确做法 |
|---|----------|-----------|-----------|
| 1 | "像"字超限 | 删最好的比喻换平叙 | 删陈词比喻，保留精准比喻，优质占比高时接受 minor |
| 2 | "像"字超限 | "像"改"如/似"骗计数器 | 不骗计数器，要么删要么保留 |
| 3 | "了"密度高 | 删语法必需的"了" | 只修短句连续"了"收尾的 AI 腔，用连词衔接 |
| 4 | 碎段多 | 删"的""了"减字数 | 用逗号/连词衔接短句成长句 |
| 5 | 对话占比低 | 直接对话转叙述摘要 | 增加有信息的直接对话（带引号+动作） |
| 6 | Tell标记词 | 删所有心理描写 | 只删标记词，保留展示性描写 |
| 7 | 确定性语气 | 所有描写都用"似乎" | 首次用推测语气，确证后升级为确定 |

### 5b.3 合理覆写机制（已由 v3.1 替代，废弃存档）

> v3.1 起 L1 规则不再阻断，"合理超阈值"统一走 lint advisory + detail-reviewer 逐条回应通道，不再使用 OVERRIDE 标记；L0 红线本就不可覆写（v2.3 起脚本强制）。以下内容存档仅供查阅历史章节，新章节禁止使用。

当某处超阈值但有明确艺术理由时，可在段落前一行添加覆写标记：
```
<!-- OVERRIDE: simile_total 龙纹觉醒的关键意象比喻，删则失神 -->
那道纹路像一条沉睡的蛇，在瓦当的裂缝里微微发颤。
```
- 每章最多 3 处覆写，必须写明规则名 + 理由
- lint 将标记处从计数中排除，并在报告中记录供审核员复核
- 审核员可否决覆写

### 5b.4 主动合规 vs 被动修复

**被动修复**（当前模式）：写完 → lint 报错 → 修 → 可能过度矫正
**主动合规**（推荐模式）：写的时候就考虑规则意图 → 自然产出合规且优质的内容

主动合规要点：
- 比喻：每章规划 3-5 处精准比喻（有叙事功能的），不堆砌
- "了"：用长句衔接代替短句堆叠，"了"自然不会过多
- 对话：面对面交锋用直接对话格式，不转述
- 短句：只在重音处用，日常叙述保持正常段落长度
- 确定性：写之前确定角色的信息状态，首次遭遇用推测语气
- **style_plan（v3.1 新增，F2 缩水版）**：写正文前在交接卡填 style_plan——metaphor_plan 规划 3-5 处精准比喻（位置/喻体/叙事功能）；交锋场景在 dialogue_plan 标注用直接对话的理由。确定性状态沿用 H3 的 cross_chapter_facts.certainty_state，不另设字段。style_plan 是"给审核员的意图上下文"：lint 报比喻超限时，detail-reviewer 据此判断哪个比喻是有计划的（留）、哪个是随手堆的（删）

## 八、重写流程

收到 `review_feedback` 后：
1. 只改问题清单列出的点位，不顺手"优化"无关段落；
2. 改完重跑 style_lint，仍须全绿；
3. 重写不超过 2 轮；第 2 轮仍被退，升级总编裁决，不再继续刷轮次。

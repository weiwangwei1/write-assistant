自主蒸馏方法论 v2

从「依赖人工反馈」到「AI 自主闭环」· 基于学术研究的改进方案

一、当前方法的瓶颈

v1 方法（双轨迭代法）验证了「文本和规则同步迭代」的有效性，但有一个根本依赖：每一轮迭代都需要人工评价来发现 gap。这导致：

  • 效率低：每轮迭代需要人介入，无法批量蒸馏多个作家
  • 主观偏差：评价质量取决于评价者的文学素养，不同人可能给出矛盾建议
  • 无法扩展：如果要蒸馏 10 个作家，需要 10 轮人工反馈循环
  • 规则不可验证：提取的规则是否准确反映了作家风格，没有量化校验
核心问题：v1 的循环是「写→人工评→改」，v2 要把中间环节替换为「写→AI自评→改」，实现自主闭环。

二、研究基础

文献检索发现三个可直接用于改进的关键技术：

1. 计算文体学：量化风格指纹

研究Stamatatos (2009) 的作者归属综述表明，最稳定的风格标记是功能词频率（的、了、在、是等）、字符 n-gram 分布、句法模式——它们反映作者无意识的习惯，不受内容主题影响 [$TRAE_REF](https://onlinelibrary.wiley.com/doi/abs/10.1002/asi.21001)。

这意味着：一个作家的风格可以被量化为具体的统计特征，而不仅仅是「感觉」。我们可以在蒸馏前先提取原作的文体学指纹，然后在生成后对比指纹差异，判断风格是否还原。

2. LLM-as-a-Judge：自动化评价

研究Zheng 等 (2023) 证明 GPT-4 评审与人类偏好一致性超过 80%，达到人类评审者之间的水平 [$TRAE_REF](https://arxiv.org/abs/2306.05685)。Liu 等 (2023) 的 G-Eval 框架进一步证明，结合思维链的 LLM 评估在主观维度上与人类高度相关 [$TRAE_REF](https://arxiv.org/abs/2303.16634)。

这意味着：可以用 AI 评审替代人工评价，前提是设计好结构化的评估 rubric（评分维度+评分标准+示例），并警惕 LLM 对自身生成文本的偏好偏差。

3. RoleLLM 四阶段框架：结构化人设提取

研究Wang 等 (2023) 的 RoleLLM 框架将角色扮演能力提取分为四阶段：画像构建→知识提取→风格模仿→指令微调 [$TRAE_REF](https://arxiv.org/abs/2310.00746)。虽然我们不做微调，但前三阶段的结构化提取思路可以直接借鉴——先建画像，再提知识，最后炼风格，而不是一上来就写规则。

三、v2 方法：四阶段自主蒸馏

基于上述研究，v2 将蒸馏流程重构为四个阶段，其中阶段 2-4 均可自主完成：

v2 自主蒸馏流程
1
文体指纹提取 需人工输入
输入作家代表作原文（至少 3 万字），用文体学方法提取量化指纹：功能词频率分布、平均句长与方差、段落长度分布、标点使用模式、高频意象词表、对话占比。输出一份「风格指纹报告」，作为后续生成和评估的客观基准。
这一步只需要提供原文，提取过程可自动化。是 v1 完全缺失的环节。
2
结构化规则提取 自主
借鉴 RoleLLM 的三阶段提取思路，分三层提取规则：
  • 画像层：作家的题材偏好、调性、母题（对应 v1 的「风格定位」）
  • 语言层：从原文中提取用词偏好、句式特征、描写习惯、对话风格（对应 v1 的「语言风格规则」），但每条规则需附原文证据——至少 2 个来自代表作的例句
  • 决策层：从原文中逆向推断作家的写作决策——「这里为什么用短句」「这里为什么留白」「这里为什么不让角色说话」，提炼为可执行规则（对应 v1 的「克制原则」）
输出初版 SKILL.md。
与 v1 的区别：v1 靠读后凭感觉写规则，v2 要求每条规则有原文证据，且决策层通过「逆向推断」而非「正面总结」获得。
3
生成 + AI 自评 + 迭代 自主
  1. 生成：用初版 SKILL 写一篇测试文章（与代表作不同场景）
  2. 自评：用 LLM-as-a-Judge 方法，按结构化 rubric 评估生成文本与原作的风格一致性
  3. 定位 gap：从评估结果中提取具体差距（哪个维度不像、哪条规则被违反）
  4. 双轨修正：改文本 + 补规则写回 SKILL（保留 v1 的双轨迭代核心）
  5. 循环：直到自评分数收敛（连续两轮分数变化 < 5%）
输出定稿 SKILL.md + 测试文章。
与 v1 的区别：评价环节从人工变为 AI 自评，可实现自主闭环。
4
指纹校验 自主
对最终生成的文本提取文体指纹，与阶段 1 的原作指纹对比。如果关键维度（功能词分布、句长分布、对话占比）偏差超过阈值，回到阶段 3 继续迭代。
这是 v1 完全没有的客观校验环节——用数据而非感觉判断「像不像」。

四、AI 自评 Rubric 设计

自评环节是 v2 的核心。基于 LLM-as-a-Judge 研究，设计以下评估 rubric：

评估维度（6 维，每维 1-5 分）

维度评估问题评分标准
语言质感 用词、句式、意象是否像该作家？ 5=几乎无法区分 / 4=像但有细微差异 / 3=整体像但偶尔出戏 / 2=部分像 / 1=不像
节奏控制 长短句交替、快慢节奏、留白是否像？ 5=节奏完全一致 / 4=基本一致 / 3=大致一致但有问题 / 2=偏差明显 / 1=完全不同
氛围营造 环境描写、光影、情绪烘托是否像？ 5=氛围一致 / 4=接近 / 3=有氛围但力度不同 / 2=氛围缺失 / 1=无氛围
人物质感 角色行为逻辑、对话风格是否像？ 5=人物真实 / 4=基本真实 / 3=偶有违和 / 2=经常违和 / 1=不像该作家笔下人物
克制程度 是否信任读者、是否过度解释？ 5=克制精准 / 4=基本精准 / 3=偶有过度解释 / 2=经常解释 / 1=通篇解释
规则遵守 SKILL 中的规则是否被违反？ 5=无违反 / 4=1处轻微 / 3=2-3处 / 2=多处违反 / 1=大量违反
偏差缓解：G-Eval 研究指出 LLM 评审存在「对自身生成文本的偏好偏差」[$TRAE_REF](https://arxiv.org/abs/2303.16634)。缓解方法：① 评审时同时给出原作片段作为参照，要求对比而非独立打分；② 评审分两轮——先独立打分，再对照原作校准；③ 设置「反向验证」——让 AI 判断「这段文字是该作家写的还是 AI 模仿的」，如果判断为「该作家写的」才算通过。

v2 保留了什么：双轨迭代的核心（改文本+补规则同步进行）依然保留——这是 v1 验证过的最有效机制。v2 改变的是评价环节（人工→AI自评）和基准建立（无→文体指纹），以及增加了客观校验（指纹对比）。

六、三个关键创新

创新1：文体指纹作为客观基准

v1 完全没有量化基准——「像不像」全靠感觉。v2 引入文体学指纹，至少在以下维度提供可量化的对比：

  • 功能词频率：的、了、在、是、他、她、一、不——这些词的使用频率反映作者的无意识习惯
  • 句长分布：平均句长、标准差、短句占比——反映节奏特征
  • 段落长度分布：反映叙事的呼吸感
  • 对话占比：对话 vs 叙述的比例
  • 标点模式：逗号/句号比、破折号频率、省略号频率——标点使用是高度个人化的

创新2：逆向推断决策规则

v1 的克制规则是在迭代中被动发现的——写了、被批评了、才知道「这里不该解释」。v2 改为主动逆向推断：拿原作的关键段落，问自己「这里作家做了一个什么选择？他选了 A 而不是 B，为什么？」

正面总结（v1）：「烟雨江南善于留白」→ 太抽象，不可执行

逆向推断（v2）：「这里角色死了，作家只写了一句'刀插在咽喉里，笑着死的'，没有写临终遗言、没有写旁人反应——他选择了省略情感高潮。为什么？因为死亡的重量不需要被解释，它自己就在那里。」→ 可执行规则：死亡场景不写遗言和旁人反应

创新3：反向验证

最终验证不只是打分，还包含一个图灵测试式验证：把 AI 生成的文本和作家原文混在一起，让另一个 AI 实例判断「哪段是原作、哪段是模仿」。如果无法区分，蒸馏成功；如果能轻易区分，差距所在就是下一轮迭代的重点。

七、v2 的局限与风险

  • LLM 自评偏差：LLM-as-a-Judge 研究指出 LLM 倾向于给自身生成文本更高分。需通过对照原作、两轮校准、反向验证来缓解，但无法完全消除
  • 文体指纹的局限：功能词频率等统计特征能捕捉「形」，但难以捕捉「神」——一个作家的哲学思辨方式、意象选择的深层逻辑，目前无法量化
  • 决策规则逆向推断的风险：推断可能错误——作家选择省略可能不是因为「信任读者」，而是因为版面限制或个人偏好。需要多个证据交叉验证
  • 自主闭环的可靠性：如果自评 rubric 本身有偏差，自主迭代可能在错误方向上收敛。建议前 1-2 轮仍有人工抽检
  • 中文文体学工具不成熟：英文有 JGAAP 等成熟工具，中文的功能词提取和 n-gram 分析需要自行实现

成功标准

  • v2 自评分数与人工评价的一致性 ≥ 75%（即自评说好的，人工也认为好）
  • v2 产出的文本在人工盲评中与 v1 产出的文本质量相当或更好
  • v2 的迭代轮数不超过 v1（即没有因为自评质量低而导致更多迭代）
  • 文体指纹校验能发现 v1 遗漏的问题（如对话占比偏差、句长分布偏差）

九、总结

v2 的核心改进：不是抛弃 v1，而是在 v1 的「双轨迭代」骨架上，增加三个新环节——
  1. 前端加文体指纹提取（建立客观基准）
  2. 中端把人工评价替换为 AI 自评（实现自主闭环）
  3. 后端加指纹校验（量化验证风格还原度）
双轨迭代依然是核心机制，但从一个「需要人盯着」的流程变成了一个「可以自己跑」的流程。

v2 的意义不在于让蒸馏结果更好（v1 在有好的评价者时已经能产出高质量结果），而在于让蒸馏过程可扩展——一个人可以同时蒸馏多个作家，而不需要每个都投入 3-5 轮深度人工反馈。

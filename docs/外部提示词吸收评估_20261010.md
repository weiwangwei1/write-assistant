## 一、处理惯例（沿用 v4.2 / v4.3 吸收外部方法论的做法）

1. 先逐条比对「我们是否已有更强机制」——已有的不重复建设；
2. 判据缺失、不可判读的条目一律不采；
3. 与既有实测矛盾的条目**记录拒绝理由**，防后续重复引入；
4. 只取可判读、可退稿的条目；落地一律「合并进既有条款 / 既有产物」，不净增规则。

## 三、不采 / 拒绝条目与理由（防复引）

### 3.1 第 11 条「增加颗粒度」——拒绝（⚠️ 高复发型建议，重点留档）

原主张：打散长句（每句 ≤15 字）；删除「虽然 / 但是 / 因为 / 所以」等逻辑词；加入五感。

拒绝理由（三条证据）：
1. 「每句 ≤15 字」＝短句连打，正是 Ch1 v7 被外部评审＋读者判「一个节奏到底，一眼AI」的病根（四诊之一）；框架已用 v9 呼吸感重构两轮修订纠正。
2. 与签名风格约束直接冲突：挂载风格包基线**句均长 40.34 字、逗句比 4.48**；且 lint 有**连词下限（3.0/千字）**——「删逻辑词」会让句句短促、更显 AI。
3. 正确解已固化：**长度变化靠段落层级排布 ＋ 短句只留重音（一章 5-8 处）**（chapter-writer 5.1 呼吸感可操作版）；本条实质危害在「短句化＋删逻辑词」两点，「加五感」不构成增量（属既有倾向库常规要求）。

结论：**拒绝，不修改框架**；落档以阻断后续重复引入。

### 3.2 第 10 条「情绪爆发对白」——不采

- 「末句必须是金句」不可判读、强迫产金句必生硬；「短句为主」与「短句只留重音」口径冲突。
- 已有覆盖：「从压抑到爆发」的节奏本身＝爽点闭环「压抑→打压→蓄力→爆发」；台词峰值由章末钩子与签名台词机制管理。

### 3.3 第 12 条「万能黄金提示词」——不采

- 通用八件套＝初始化流程＋章节循环＋交接卡契约的子集；「情绪张力＋伏笔＋反转」已被爽点 / 伏笔 / 债体系**更精确**覆盖。无增量。

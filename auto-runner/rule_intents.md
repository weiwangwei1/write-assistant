# 规则意图文档 (Rule Intents) v1.0

> **目的**：为 style_lint.py 的每条规则文档化「为什么存在 / 正确修法 / 过度矫正警告」。
> **注入位置**：chapter-writer 写作前上下文（~2000 tokens 预算）。
> **核心问题**：当前写手只知道「不能做什么」，不知道「为什么不能」和「应该怎么做」，
> 导致修 lint 时过度矫正——删了好的、留了坏的、语法也坏了。

---

## 一、根因总览：为什么框架会导致文学性退步？

当前框架有 7 个架构级问题，导致「修 lint → 文学性退步」的恶性循环：

| # | 根因 | 表现 | 后果 |
|---|------|------|------|
| RC1 | **反应式修复模式** | 写→lint报错→最小修改→引入新问题 | 修了A坏了B，补丁摞补丁 |
| RC2 | **钝规则 vs 语义质量** | 计数"像"但不分好坏；计数"了"但不分语法必需 vs AI腔 | 好比喻和烂比喻一起删 |
| RC3 | **缺失规则意图传递** | 规则只说"≤8处"不说"因为AI堆叠比喻" | 写手不理解意图就乱砍 |
| RC4 | **对话规则无场景感知** | "对话35-60%"不分场景类型一刀切 | 面对面交锋被转成叙述摘要 |
| RC5 | **无合理覆写机制** | 超阈值只能删内容或hack绕过 | "像"改"如"——骗计数器不提质 |
| RC6 | **反馈不回流** | 人工反馈只修当前章，不进框架 | 同一错误章章重犯 |
| RC7 | **规则误报诱导过度矫正** | 正则太宽泛，"总说""公道"被误判为对话动词 | 写手去"修复"正常段落，反而破坏文学性 |

**核心矛盾**：框架把写作当作**合规检查**（rules → pass/fail），
而不是**工艺优化**（principles → quality）。

| 根因 | 解决方案 | 状态 | 位置 |
|------|---------|------|------|
| RC1 反应式修复 | 5b 节「文学质量主动引导」+ 三条铁律 | ✅ 已实施 | chapter-writer SKILL.md |

| RC3 缺失规则意图 | rule_intents.md 逐规则文档化意图/正确修法/过度矫正警告 | ✅ 已实施 | auto-runner/rule_intents.md |

## 二、逐规则意图文档

### 2.1 比喻规则 (simile_total / simile_stacked)

| 维度 | 内容 |
|------|------|
| **规则** | "像"字比喻 ≤8/章（L1）；一段一喻（L0） |
| **为什么存在** | AI 生成文本的典型特征是**比喻堆叠**——连续多个"像X像Y像Z"，信息冗余且缺乏精准度。人类作家用比喻是**精准打击**：一处比喻承担一个叙事功能（暗示氛围/外化情绪/建立通感），不是装饰。 |
| **v2.2 改进** | 比喻质量分级——优质比喻（喻体具体、不在陈词表）占比≥70%时，超限从 critical 降级为 minor。允许保留有效比喻。 |
| **✅ 正确修法** | 删掉陈词比喻（像山一样/像火一样），保留精准比喻（像一锅将开未开的水——有温度有状态有张力）。如果超限但优质占比高，lint 只报 minor，可保留。 |
| **❌ 过度矫正** | 把最好的比喻删掉换成平铺直叙。"一锅将开未开的水"→"喧嚣拢成一团"——**这是退步**。比喻有信息增量（暗示能量积蓄未爆发），平叙没有。 |
| **❌ Hack 绕过** | 把"像"改成"如/似/仿佛"来骗计数器——lint 看不到"像"了，但比喻堆叠问题还在，且"如"字多了又是另一种 AI 腔。**不要骗计数器，要么删要么保留并接受 minor。** |

### 2.2 功能词规则 (le_overuse / le_pattern / zhe_overuse)

| 维度 | 内容 |
|------|------|
| **规则** | "了"≤60/千字（L2 minor）；"着"≤25/千字（L2 minor）；短句(≤15字)以"了"收尾≤3处（L2 minor） |
| **为什么存在** | AI 文本的"了"密度偏高，但真正的问题不是"了"多，而是**短句连续以"了"收尾**——这是 AI 的节奏标记，每个短句都用"了"来制造虚假的完成感。人类作家的"了"是语法必需（状态变化标记），不是节奏填充。 |
| **v2.2 改进** | "了"密度保留作指纹参考（minor），新增 le_pattern 检测——只报短句以"了"收尾的 AI 腔模式，不报语法必需的"了"。 |
| **✅ 正确修法** | 把连续的短句"了"用连词衔接成长句。"灯灭了。人散了。街空了。"→"灯灭了，人散了，街也空了下来。"——用逗号衔接，保留语法必需的"了"。 |
| **❌ 过度矫正** | 删除语法必需的"了"导致句子不完整。"老灯累"（缺"了"）→ 语法残缺，读者以为打字漏了。正确是"老灯乏了"或"老灯暗了"。 |
| **❌ 过度矫正** | "泛暗光"→ 应为"泛了层暗光"。"密"是状态变化，需要"了"标记变化完成。删除"了"让状态变化变成了静态描述，语义改变。 |

### 2.3 对话规则 (dialogue_ratio / narrative_dialogue)

| 维度 | 内容 |
|------|------|
| **规则** | 对话占比 35-60%（L1）；叙述化对话≤2处（L2 minor） |
| **为什么存在** | 对话占比过低通常是 AI 偏好叙述概述、缺乏人物声音。但对话占比不是越高越好——大量对话被转成"X问Y说Z"的叙述化摘要，虽然字数算对话但失去现场感。面对面交锋场景必须用直接对话格式（带引号），保留语气、停顿、表情。 |
| **v2.2 改进** | 新增 narrative_dialogue 检测——识别无引号的"X问Y说Z"模式，提醒写手面对面场景应用直接对话格式。 |
| **✅ 正确修法** | 对话占比低时，增加有信息的直接对话（带引号+动作描写），不要把已有对话从直接格式改成叙述格式来"凑"占比。面对面场景永远用直接对话。 |
| **❌ 过度矫正** | 把直接对话转成叙述摘要。"霍东来说：'这瓦当不对。'"→"霍东来说瓦当不对"——**失去现场感**。对话有语气、有距离感、有节奏；转述是摘要，读者觉得隔了一层。 |
| **场景感知** | 探索/独处场景对话自然偏少（可<35%），不用强行加对话。交锋/谈判/教学场景对话自然偏多（可>60%）。lint 报 minor 时根据场景判断是否需要修。 |

### 2.4 句式规则 (short_para_ratio / short_para_run / not_a_is_b)

| 维度 | 内容 |
|------|------|
| **规则** | 碎段(≤15字)占比≤45%（L1）；连续碎段≤6段（L1）；"不是A—是B"≤2/章（L0） |
| **为什么存在** | AI 文本的典型节奏是**全短句**——每句都是独立的短段落，缺乏长短交替。人类作家用短句做重音（情绪高点、反转瞬间），用长句做铺垫（推理、氛围、动作连贯）。"不是A是B"是 AI 的对比句式，用多了像在写议论文。 |
| **✅ 正确修法** | 把连续短句用连词/逗号衔接成长句，保留 1-2 个短句做重音。"天黑了。风停了。门响了。"→"天黑了，风也停了——门响了。"——前两个短句衔接成铺垫，最后一个短句独立做冲击。 |
| **❌ 过度矫正** | 把所有短句都合并成长句——失去了短句的节奏功能。短句在重音处是武器，不能全删。每章应有 1 个 ≥200 字的长段做节奏对比，但也要有短句做冲击。 |
| **❌ 过度矫正** | 为了减少碎段而删除"的""了"等连接词——"泛暗光"不如"泛着暗光"自然。减少碎段的正确方式是衔接句子，不是删连接词。 |

### 2.5 展示 vs 告诉规则 (tell_marker / emotion_telling / ban_summary_voice)

| 维度 | 内容 |
|------|------|
| **规则** | Tell标记词检测（L2 minor）；情绪直说词≥3次报警（L3）；总结式心声0容忍（L0） |
| **为什么存在** | AI 文本习惯"告诉"读者角色的心理状态（"他不禁感到害怕"），而不是通过行为"展示"（"他的手不受控地攥紧了袖口"）。Tell标记词（习惯性地/下意识地/不由得）描述动作的心理机制而非动作本身——读者不需要知道这是"习惯性的"，看到第四次就知道是习惯了。 |
| **✅ 正确修法** | 删除Tell标记词，让动作本身说话。"左手习惯性地在桌沿叩了两下"→"左手在桌沿叩了两下"——读者看到重复出现自然知道是习惯。 |
| **❌ 过度矫正** | 把所有心理描写都删掉——适度的内心独白是必要的，关键是"展示心理过程"而非"宣告心理状态"。"他犹豫了"是Tell；"他的手停在门把上，三秒后才按下"是Show。 |
| **边界** | 不是所有"告诉"都坏——转场时用一两句概述加快节奏是合理的。关键是不要在**情绪高潮**和**关键发现**处用Tell，那些地方必须Show。 |

### 2.6 确定性匹配规则 (certain_marker_mismatch)

| 维度 | 内容 |
|------|------|
| **规则** | 观察+确定语气检测（L2 minor）；角色确定性状态追踪（H3 交接卡字段） |
| **为什么存在** | 视角漂移是 AI 写作的隐蔽问题——角色第一次遭遇某事物时，描写使用了确定语气（"看着就是X"），表明角色知道了不该知道的信息。人类作家在角色首次遭遇时用推测语气（"倒像是X"/"似乎是X"），随信息积累逐步升级到确定。 |
| **✅ 正确修法** | 首次遭遇用推测语气（像是/似乎/倒像是/好像/仿佛），信息确证后用确定语气（就是/分明是）。在交接卡 certainty_state 中标注每个角色的确定程度。 |
| **❌ 过度矫正** | 所有描写都用推测语气——已确证的信息仍用"似乎"会让角色显得迟钝。确定性应随信息积累升级，不是永远不确定。 |
| **示例** | "看着就是专门候着谁的"→"倒像是专门候着谁的"——许愿第一次见公会的人，不可能"确定"对方在等谁。"倒像是"保留推测语气，贴合角色认知。 |

### 2.7 标点指纹规则 (dash_overuse / ellipsis_overuse)

| 维度 | 内容 |
|------|------|
| **规则** | 破折号≤X/千字（L2）；省略号≤X/千字（L2）；阈值由风格包按原作指纹设定 |
| **为什么存在** | 不同作者的标点使用频率差异极大（辰东破折号 0.074/千字，今何在 4.6/千字）。标点频率是作者身份的量化指纹。超限意味着偏离了目标风格。 |
| **✅ 正确修法** | 减少不必要的破折号——很多破折号可以用逗号替代。"他走了——回头看了一眼"→"他走了，回头看了一眼"。保留有叙事功能的破折号（转折/补充/中断）。 |
| **❌ 过度矫正** | 全部删除破折号——有些破折号承担着语气转折功能，删了句子变平。优先删连续使用和装饰性使用，保留有信息增量的。 |
| **风格包联动** | 烟雨江南破折号极低（0/千字），辰东也极低（0.074/千字），今何在很高（4.6/千字）。挂载风格包后阈值自动调整。 |

## 三、过度矫正模式速查表

写手修 lint 时最容易犯的 7 种过度矫正：

| # | lint 报错 | ❌ 错误修法 | ✅ 正确修法 |
|---|----------|-----------|-----------|
| 1 | "像"字超限 | 删掉最好的比喻换成平叙 | 删陈词比喻，保留精准比喻；优质占比≥70%时接受 minor |
| 2 | "像"字超限 | "像"改"如"骗计数器 | 不骗计数器——要么删要么保留并接受 minor |
| 3 | "了"密度高 | 删所有"了"包括语法必需的 | 只修短句连续"了"收尾的 AI 腔模式，用连词衔接 |
| 4 | 碎段多 | 删"的""了"等连接词减字数 | 用逗号/连词衔接短句成长句 |
| 5 | 对话占比低 | 直接对话转叙述摘要 | 增加有信息的直接对话（带引号+动作） |
| 6 | Tell标记词 | 删所有心理描写 | 只删标记词（习惯性地/下意识地），保留展示性描写 |
| 7 | 确定性语气 | 所有描写都用"似乎" | 首次遭遇用推测语气，确证后升级为确定语气 |

## 四、合理覆写机制（v2.2 新增）

当写手有明确艺术理由需要超阈值时，可在正文对应段落前一行添加覆写标记：

```
<!-- OVERRIDE: simile_total 龙纹觉醒的关键意象比喻，删则失神 -->
那道纹路像一条沉睡的蛇，在瓦当的裂缝里微微发颤。
```

**规则**：
- 每章最多 3 处覆写（防止滥用）
- 覆写必须写明规则名 + 理由
- lint 读取覆写标记后，将该处从计数中排除
- 覆写记录在 lint 报告中供审核员复核
- 审核员可否决覆写（否决则写手必须修改）

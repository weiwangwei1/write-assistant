两个仓库我都熟，这个问题其实正好卡在两边的设计哲学交汇点上——writeStyle 的方法论 v2 已经把"风格"拆成了**可量化的文体指纹**和**定性的决策规则**两半，而 write-assistant v3.0 刚把规则体系按"可校验性"分完层。接入方案就顺着这个共同逻辑走：**把作者文风做成可插拔的"风格包"，指纹进脚本、决策卡进提示词，两半各有自己的校验闭环**。下面是具体修改建议。

## 一、总原则：风格包 = 指纹 + 决策卡 + lint 覆盖层

不要把辰东/烟雨江南的 SKILL.md 整份塞进 chapter-writer——那是 73KB 灾难的重演。每个作者风格包拆成三个文件：

```
.trae/skills/writer-styles/
  chendong/
    style_card.md        # 风格决策卡：核心决策≤10条，每章注入（1-2k tokens）
    fingerprint.json     # 文体指纹基线：从原作统计出的量化指标
    lint_overlay.json    # lint 阈值覆盖层：该风格的签名手法豁免与专属阈值
    reference/           # 完整版 SKILL.md + 原文例句库（仅蒸馏和人工查阅用）
  yanyujiangnan/
    ...
```

`novel_config.json` 加一行：

```json
"style_pack": "yanyujiangnan",
"style_mix": null
```

总编派单时把对应风格包注入写手上下文。**一本书只挂一个风格包**，融合配方等你单风格跑稳一卷再说（archive 里那次 fusion 实验的教训先消化完）。

## 二、各部分的具体改法

### 1. chapter-writer：注入的是"决策卡"，不是全文

从 writeStyle 的 SKILL.md 里提炼每章必用的东西，压成 ≤10 条决策 + 指纹目标值。以烟雨江南为例，决策卡大概是：

- 比喻必须功能性＞装饰性，喻体取自本世界物质（这条是决策，进提示词）
- 高潮段落排比造势，日常段落允许"粗糙句"（决策）
- 对话占比目标 25-35%、单章 3000-5000 字（**指纹指标，不进提示词，进 lint**）

注意分水岭：**"为什么这样写"进决策卡，"写出来什么样"进指纹**。前者靠 LLM 理解，后者靠脚本验收——和你们 v2 方法论里"复现决策而非抄句子"的结论一致。

### 2. style_lint.py：加 `--style` 模式（这是核心改动）

两个新能力：

**a) 阈值覆盖层**。通用反 AI 红线（不是A是B、碎段率、比喻堆叠）对所有风格生效，但**作者的签名手法必须豁免**，否则 lint 会把风格本身当病治：

```json
// lint_overlay.json（辰东示例）
{
  "four_char_cliches": {"disabled": true, "reason": "辰东签名手法=四字短语堆叠气势"},
  "simile_max_per_chapter": 12,
  "short_para_ratio_max": 0.55,
  "custom_required": [
    {"rule": "naming_system", "check": "武器/境界/材料命名禁用通货词：仙器|法宝|神器", "severity": "critical"}
  ]
}
```

反过来，烟雨江南的覆盖层会**收紧**某些项（比如要求结尾极短句占比、禁用通货意象清单）。"必须有粗糙的句子"这种甚至可以做成 lint 检查：金句密度过高反而报警——你们复盘文档里自己写过"如果每句都是金句，那就没有金句了"。

**b) 指纹对比模式**。把方法论 v2 阶段 1 和阶段 4 脚本化：

```bash
# 蒸馏期：从原作提取指纹基线
python style_fingerprint.py build 原作合集.txt --out fingerprint.json

# 量产期：每章对比
python style_fingerprint.py check chapter_013.txt --baseline fingerprint.json
```

指纹指标就用你们 v2 里定的那套：功能词频率分布（的/了/在/是/不）、平均句长与方差、段落长度分布、对话占比、标点模式（逗号句号比/破折号频率）。对比算偏差值，超阈值报 critical——这是客观校验，和 LLM 自评完全独立。

### 3. de-ai-processor：加"签名豁免"前置步骤

现在 de-ai 的 14 项清单是通用的，接入风格包后必须先读 `lint_overlay.json` 的豁免表再动手。否则会出现最荒诞的事故：**去AI化师把辰东的四字堆叠当"四字词组堆砌症"全删了，风格当场死亡**。通用清单管"AI 腔"，豁免表保"作家腔"，边界就是 lint 覆盖层。

### 4. quality-reviewer：rubric 加一维"风格契合度"

你们 v2 方法论里的 6 维 rubric 直接借过来一维："语言质感——用词、句式、意象是否像该作家？"注意沿用方法论里的**偏差缓解**设计：评审时附原作片段做对照打分，而非独立打分；必要时用"反向验证"（让评审猜这段是作家写的还是 AI 仿的）。评审报"不像"时必须指出具体维度（用词？节奏？意象？），不允许只给感觉分。

### 5. 新增 style-distiller（离线工具型 agent，不进日常流水线）

把方法论 v2 的四阶段固化成可复用流程，蒸馏新作者时走一遍：

```
① 投喂原作≥3万字 → style_fingerprint.py build 生成指纹基线
② 结构化三层提取（画像层/语言层/决策层，每条规则附原文证据）→ 初版 style_card
③ 写测试章 → LLM-as-judge 6维rubric → 双轨迭代（改文本+补规则）
④ style_fingerprint.py check 校验关键维度偏差 → 收敛则定稿风格包
```

产出物就是第一节说的三件套。这样"蒸馏第三个作者"就是标准化操作，不用再从头摸索。

### 6. memory-manager：加风格漂移监控

300 章的量产里，风格会随上下文窗口缓慢漂移（写到 100 章后"像辰东"的程度必然衰减）。建议：每 10 章一致性自检时附带跑指纹对比，把偏差值记进 `memory/style_drift.jsonl`，连续 3 章偏差上升→总编收到告警→用决策卡+fingerprint 做一次校准章。长线漂移是 LLM 写作特有、人工写作没有的问题，必须有机制兜底。

## 三、落地顺序（四步）

1. **先做指纹脚本**（`style_fingerprint.py`）：从 writeStyle 的辰东四部/烟雨江南三部原文提取基线，这是唯一没有替代品的硬资产；
2. **用黄金三章做校准闭环**：挂风格包写三章 → 指纹对比 + rubric 评审 → 调 lint_overlay 阈值和决策卡 → 定稿后才量产（这就是你们双轨迭代法在风格维度的复用，三轮为限）；
3. **改造 lint 与 de-ai 的豁免链路**；
4. **量产 + 漂移监控**。

## 四、三个风险提醒

- **风格包和 v3.0 硬约束的仲裁**：H2（lint 全绿）仍是最高优先级，lint_overlay 只能调整阈值和豁免签名手法，不能关掉"不是A是B"这类通用反AI项——烟雨江南本人也不会一章写 11 个"不是…是…"，那不是他的风格，是 AI 的风格。区分"作家签名"和"AI 指纹"的标准：原作的指纹基线里有没有这个特征。
- **决策卡信息量控制在 2k tokens 内**，否则每章注入成本会吃掉上下文预算（现在预算 8-10k）；
- **别急着做风格融合**。融合配方意味着两套指纹基线，偏差判定会互相干扰，单风格先稳定产出一卷。

## 已入库的改动

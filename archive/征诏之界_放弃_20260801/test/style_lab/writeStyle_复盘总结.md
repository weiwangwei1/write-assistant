### writeStyle 独有且值得提取的部分

#### ★ 1. Few-shot 样本按场景类型选取机制

**writeStyle 做法**：将原文分为5类场景（描写/整章/战斗/对话/心理），生成时按场景选2-3段原文作为风格锚点。

**当前系统缺失**：style_card 注入时只有原则和阈值，没有按场景类型分类的原文样本库。写手拿到的是"规则"而非"范本"。

**价值**：高。LLM 的上下文学习（in-context learning）对 Few-shot 样本的依赖远强于规则指令。同样写战斗场景，给2段烟雨江南的战斗原文比给10条规则更有效。

**提取方案**：
```
test/style_lab/
└── few_shot_samples/
    ├── yanyujiangnan/
    │   ├── battle.json      # 5-10段战斗原文
    │   ├── dialogue.json    # 5-10段对话原文
    │   ├── environment.json # 5-10段环境原文
    │   ├── psychology.json  # 5-10段心理原文
    │   └── full_chapter.json # 2-3段整章原文
    └── [其他作者]/
```
每段原文 500-2000 字，标注来源作品和场景类型。生成时由 chapter-writer 按当前场景类型自动选取。

#### ★ 2. 战斗机制参考表（世界观骨架）

**writeStyle 做法**：从3部原文提取力量体系（能力域/等级/构装/原力），形成结构化表格。写战斗时不用临场编造，直接从表中选取组合。

**当前系统缺失**：style_card 有"信息在对抗中释放"原则，但没有具体的世界观机制参考表。test/experiments 有 S18 空间感维度，但没有力量体系结构。

**价值**：中高。对《征诏之界》来说，征调/副本流有自己的体系（征诏令/功勋/裂缝），但 writeStyle 的"力量体系嵌入方式"（观察式 vs 说明书式）和"战斗节奏控制表"（对峙→交锋→转折→收束）是通用的。

**提取方案**：战斗节奏控制表和力量体系嵌入方式提取到 craft_guide.md 的补充章节；生物兵器描写要素5条可作为 S19 空间感的战斗子维度。

#### ★ 3. 对比修正 Prompt 模板（轻量 DPO 替代）

**writeStyle 做法**：4个 Prompt 模板（场景生成/整章生成/续写/对比修正），其中"对比修正"模板让 LLM 拿生成段与原文同场景段逐维度对比，找最大偏差重写。

**当前系统缺失**：detail-reviewer 和 quality-reviewer 做宏观审核，但没有"与原文同场景直接对比"的轻量操作。style_fingerprint.py 做的是统计偏差检测，不是场景级对比。

**价值**：中。对蒸馏迭代阶段有用，对日常写作流水线用处不大（流水线已有 detail-reviewer）。

**提取方案**：对比修正模板可作为 style_lab 的"蒸馏迭代工具"保留，不入正式流水线。

#### ★ 4. 迭代记录表模板

**writeStyle 做法**：简单表格（轮次/场景/像不像1-5/主要偏差/修正方向），5轮后回顾。

**当前系统缺失**：rubric_review.md 存在但偏重（6维rubric评分），writeStyle 的轻量表更适合快速迭代。

**价值**：低。当前 rubric_review.md 已够用，且更严谨。

#### ★ 5. 五条战斗描写原则

**writeStyle 做法**：动作不停/机制嵌入观察/保留氛围铺垫/砍掉解释性段落/砍掉游戏面板。

**当前系统对比**：test/experiments 有 S6 战斗呼吸（"这一击之后，对手的下一个身体动作是什么"）和 S18 空间感，但没有 writeStyle 的"砍掉游戏面板"和"机制嵌入观察"这两条。

**价值**：中。"砍掉游戏面板"（不写能量百分比/护盾次数）和"机制嵌入观察"（用"甲壳接缝泛着暗光"代替"甲壳厚度3厘米"）是实用的写作指导，当前系统没有覆盖。

**提取方案**：作为 craft_guide.md 的补充条目 S19-S20，或并入 S6 战斗呼吸的扩展说明。

## 四、writeStyle 的经验教训

### 成功经验（可复用）

1. **对话内上下文学习可行**：不用微调，用系统提示词 + Few-shot 样本就能让 LLM 近似目标风格。7轮迭代从 5.2 到 7.7，证明了迭代修正的有效性。

2. **量化参数比形容词有效**："句长29字"比"以中短句为主"更可执行。这验证了当前 style_card 用量化决策（"了≤25/千字"）而非倾向性描述的方向。

3. **机制参考表解决"临场编造"**：战斗场景最大的问题是 LLM 编造力量体系导致不一致。结构化参考表让生成有据可依。

4. **过矫正需要回调**：R5 追求句硬节奏→过度碎句，R7 回调找平衡。这与《征诏之界》v7 重写中"换词策略导致语义模糊"的教训一致。

### 失败教训（已避免）

1. **自检清单不可靠**：writeStyle 的7项自检靠人工执行，实际执行率未知。当前系统用 style_lint.py 自动化校验，执行率100%。

2. **未覆盖非战斗场景**：writeStyle 7轮迭代全部基于战斗，对话/环境/整章未测试。当前 style_lab 8阶段分析覆盖所有场景类型。

3. **无章际分布统计**：writeStyle 的"句长29字"是全本均值，无波动范围。当前 fingerprint v2.0 有章际分布（mean/stdev/p5/p95），容差从波动推导。

4. **风格基线未用原作验证**：writeStyle 的参数来自人工提取，未做 selfcheck。当前 fingerprint v2.0 有 selfcheck 命令验证容差区分效度。

## 一、v2.0 评估：做对了什么，做错了什么

### 1.1 v2.0 验证数据（三章 v7）

| 维度 | Ch1 | Ch2 | Ch3 | 判定 |
|------|-----|-----|-----|------|
| P1 意象感知 | 0 | 20 | 12 | **崩塌** |
| P2 金句密度 | 100 | 60 | 63 | 误判 |
| P3 重复动作 | 84 | 80 | 100 | **有效** |
| P4 替代词质量 | 40 | 28 | 40 | 诊断对、建议错 |
| P5 指代密度 | 100 | 85 | 85 | **有效** |
| 综合 | 61.8 | 51.8 | 57.8 | 偏低 |

### 1.2 做对了什么

1. **P4 发现了"打地鼠"模式**：`口子`18次 > `裂缝`2次，`砂`17次 > `碱味`2次——替代词本身变成新的高频词。诊断准确。
2. **P3 控住了情绪指标动作**：磨刀速度变化 Ch1=6/4, Ch2=7/4 超限，Ch3=3/4 达标。机制有效。
3. **P5 指代密度**：`那枚` Ch2=16/4 超限，`它` Ch3=12/8 超限。检测有效。

### 1.3 五个根本缺陷

#### 缺陷1：P1 评分崩塌——惩罚天然通道

```
暗紫色是色彩意象 → 天然走视觉通道 → 连续3次视觉 → 扣8分
裂缝是视觉意象 → 天然走视觉通道 → 连续3次视觉 → 扣8分
```

Ch1 中 `暗紫色` 有5组连续同通道、`磨刀` 有3组、`裂缝` 有6组，合计 14×8=112 分扣分 → `max(0, 100-112)` = 0。

**问题本质**：检测"是否连续走视觉"是错误的问题。正确的问题是"是否**只**走视觉，从不走其他通道"。色彩意象走视觉是正常的；但如果 18 次出现全部是视觉命名、没有一次走听觉/触觉/嗅觉——那才是问题。

#### 缺陷2：P4 建议自相矛盾

```
v7 把"裂缝"换成"口子" → "口子"出现18次 → P4 建议"恢复'裂缝'使用"
但当初换掉"裂缝"就是因为它出现太频繁 → 回到原词 = 回到原问题
```

**问题本质**：建议"换回原词"是在同一个感知通道（视觉）里打转。真正的解决方案不是换词，是**换感知方式**：不写"裂缝"也不写"口子"，而是写"风从那里灌进来"（触觉）、"磨石声从那边传来"（听觉）、"碱味从那个方向浓了"（嗅觉）。

#### 缺陷3：全量硬编码

```python
IMAGERY_GROUPS = {"暗紫色": ..., "碱味": ..., "铜钱": ..., "磨刀": ..., "裂缝": ...}
RECURRING_ACTION_PATTERNS = {"磨刀速度变化": ..., "铜钱翻转动作": ..., "手抖/脸平静对比": ...}
REFERENTIAL_PATTERNS = {"那几枚": ..., "那枚": ..., "它": ..., "掌中之物": ...}
```

全部针对《征诏之界》写死。换一本书，需要手工重新配置所有意象组、动作模式、代词模式。

#### 缺陷4：只查词频不查感知

框架检测"口子出现18次"，但不检测"18次都是视觉命名"。真正的问题不是哪个词用了几次，而是**每次出现时角色通过什么感官通道感知它**。

#### 缺陷5：P2 误判短句

```
"安静。"（2字）→ 判为金句（philosophical_markers 匹配"安静"）
"程铖没动。"（5字）→ 判为金句
"像在回应什么。"（7字）→ 判为金句
```

短陈述句被误判为哲理收尾句。Ch2 的 heavy 段占比 17.6%（目标≤10%），但其中大量是误判。

## 二、v3.0 核心范式转移

### 2.1 范式对比

| | v2.0 词频追踪 | v3.0 感知维度追踪 |
|---|---|---|
| 检测对象 | 哪个词用了几次 | 每次出现走哪个感知通道 |
| 问题定义 | "口子"出现18次 | 18次全是视觉，没有一次走听觉/触觉/嗅觉 |
| 解决方向 | 换个词 | 换感知方式 |
| 效果 | 打地鼠（换了又换） | 同一个词，不同维度 |
| 配置方式 | 硬编码意象组 | 自动发现高频名词 |
| 跨章追踪 | 无 | 有（演化曲线） |

### 2.2 核心洞察

**意象重复的真正问题不是词频，是感知维度单一。**

当一个意象出现 18 次，如果每次都通过不同感官通道（第1次看颜色、第3次听声音、第5次闻气味、第7次摸温度、第9次感受对周围的影响），读者不会觉得重复——因为每次都是新的感知。

反之，如果 18 次全是"看到那道口子""口子在发光""口子边缘发紫"——即使换了词（口子→裂缝→界门），读者仍然觉得重复，因为感知方式没变。

**v3.0 的核心检测目标**：对每个高频名词，追踪每次出现时的感知通道，计算感知维度覆盖率。

## 三、五维架构设计

### A1. 感知维度覆盖（Perception Aspect Coverage）

**检测目标**：高频名词的每次出现走哪个感知通道，非视觉通道占比多少。

#### 3.1.1 感知通道定义

```python
PERCEPTION_CHANNELS = {
    "视觉": {
        "keywords": ["光", "亮", "暗", "紫", "色", "看", "望", "盯", "瞧", "影", "闪", "亮起", "发紫", "暗色", "纹路"],
        "weight": 1.0,  # 基础权重
    },
    "听觉": {
        "keywords": ["声", "响", "磨", "碎", "哑", "咯吱", "听", "嗡", "嘶", "劈", "碰", "刮", "嗡嗡"],
        "weight": 1.2,  # 非视觉通道加权（鼓励多样性）
    },
    "嗅觉": {
        "keywords": ["味", "碱", "焦", "臭", "腥", "香", "闻", "气", "烟", "炊烟", "泔水", "铁锈"],
        "weight": 1.2,
    },
    "触觉": {
        "keywords": ["烫", "凉", "冷", "热", "暖", "寒", "摸", "碰", "握", "攥", "捏", "糙", "滑", "涩", "硬", "软", "硌", "疼", "干热", "干涩"],
        "weight": 1.2,
    },
    "效应": {
        "keywords": ["风", "灌", "吹", "渗", "爬", "蠕动", "收", "放", "变", "裂", "合", "关", "开"],
        "weight": 1.0,  # 效应通道：描述意象对周围环境的影响
    },
}
```

#### 3.1.2 检测算法

```
输入：章节文本
输出：每个高频名词的感知通道分布

1. 自动发现高频名词（见 A3）
2. 对每个高频名词：
   a. 找到所有出现位置（段落号 + 上下文窗口）
   b. 对每次出现，取前后20字作为上下文窗口
   c. 在上下文窗口中匹配感知通道关键词
   d. 选择命中数最多的通道作为该次出现的感知通道
   e. 统计通道分布：{视觉: 12, 听觉: 2, 触觉: 1, 嗅觉: 3, 效应: 0}
3. 计算覆盖率 = 非视觉出现次数 / 总出现次数
```

#### 3.1.3 评分公式

```
覆盖率 = 非视觉出现次数 / 总出现次数

评分：
  覆盖率 ≥ 0.4 → 100（感知维度丰富）
  覆盖率 0.25-0.4 → 80（有尝试但不够）
  覆盖率 0.1-0.25 → 50（基本只有视觉）
  覆盖率 < 0.1 → 20（感知维度严重单一）

额外扣分：
  总出现次数 > 15 且覆盖率 < 0.1 → 额外扣20分（高频+单一=最严重）
```

#### 3.1.4 报告输出示例

```json
{
  "noun": "口子",
  "total_occurrences": 18,
  "channel_distribution": {
    "视觉": {"count": 15, "ratio": 0.83},
    "听觉": {"count": 1, "ratio": 0.06},
    "触觉": {"count": 1, "ratio": 0.06},
    "嗅觉": {"count": 1, "ratio": 0.06},
    "效应": {"count": 0, "ratio": 0.0}
  },
  "coverage_ratio": 0.17,
  "score": 50,
  "diagnosis": "18次出现中15次走视觉通道，非视觉覆盖率仅17%。意象感知维度严重单一。",
  "suggestion": "不需要换词。尝试：第5次写口子附近的风声（听觉），第9次写口子边的温度变化（触觉），第13次写口子散发的气味（嗅觉）。"
}
```

### A2. 替代词通道转移（Substitution Channel Transfer）

**检测目标**：当写手用替代词替换原词时，感知通道是否随之改变。

#### 3.2.1 检测算法

```
输入：章节文本 + 高频名词组（原词+变体列表，从 A3 获得）

1. 对每个高频名词组：
   a. 统计原词每次出现的感知通道
   b. 统计每个变体每次出现的感知通道
   c. 计算通道转移率 = 变体非视觉占比 - 原词非视觉占比

2. 判定：
   - 通道转移率 > 0.1 → "有效转移"（替代词带来了新感知维度）
   - 通道转移率 -0.1 ~ 0.1 → "同通道平移"（换词不换感知，打地鼠）
   - 通道转移率 < -0.1 → "退步"（替代词比原词更单一）
```

#### 3.2.2 评分公式

```
对每个高频名词组：
  如果变体出现次数 ≥ 5（足够样本）：
    转移率 > 0.1 → 不扣分
    转移率 -0.1~0.1 → 扣10分（同通道平移）
    转移率 < -0.1 → 扣15分（退步）
  否则：不评分（样本不足）

A2 总分 = max(0, 100 - 总扣分)
```

#### 3.2.3 与 v2.0 P4 的关键区别

| | v2.0 P4 | v3.0 A2 |
|---|---|---|
| 检测对象 | 变体词频 vs 原词词频 | 变体感知通道 vs 原词感知通道 |
| 判定标准 | 变体 > 原词 = 退化 | 通道没变 = 同通道平移 |
| 建议 | "恢复原词" | "不换词，换感知方式" |

**核心改变**：v2.0 认为"变体比原词多"就是问题；v3.0 认为"变体和原词走同一通道"才是问题。如果变体虽然出现多但带来了新感知通道，那是好事不是坏事。

### A3. 高频名词自发现（Auto-Discovery）

**检测目标**：自动发现文本中的高频名词，不依赖硬编码配置。

#### 3.3.1 发现算法

```
输入：章节文本
输出：高频名词列表 + 变体分组

1. 分词（简化版）：
   a. 提取所有2-4字中文词组（连续中文字符段）
   b. 过滤停用词（的、了、是、在、他、这、那、一、不...）
   c. 过滤动词/形容词（通过后缀模式：看、听、走、跑、亮、暗...）

2. 词频统计：
   a. 统计每个词组出现次数
   b. 筛选出现 ≥ 5 次的词组

3. 变体分组：
   a. 对高频词组，检查是否存在语义近似的变体
   b. 近似判定规则：
      - 共享核心字（"裂缝"和"裂纹"共享"裂"）
      - 上下文共现（经常出现在同一段落的词组）
      - 人工配置覆盖（可选：config 文件中指定分组）

4. 输出分组：
   {
     "裂缝": {
       "core": ["裂缝"],
       "variants": ["口子", "界门", "裂纹", "石缝"],
       "total": 35
     },
     ...
   }
```

#### 3.3.2 停用词表

```python
STOP_WORDS = {
    # 代词
    "他", "她", "它", "这", "那", "其", "之",
    # 量词
    "个", "只", "条", "道", "枚", "件", "步", "次",
    # 助词
    "的", "了", "是", "在", "也", "都", "就", "还", "又", "才",
    "不", "没", "有", "一", "两", "三", "四", "五", "六", "七", "八", "九", "十",
    # 连词
    "和", "与", "或", "但", "而", "则", "便", "即",
    # 方位
    "上", "下", "里", "外", "前", "后", "中",
}

# 动词/形容词后缀（用于过滤）
VERB_SUFFIXES = ["着", "过", "了", "起", "下", "出", "进", "来", "去", "到"]
```

#### 3.3.3 人工配置覆盖（可选）

```json

  "manual_groups": {
    "裂缝": {
```

### A4. 感知-身体关联（Perception-Body Linkage）

**检测目标**：意象出现时，角色身体有没有反应。纯视觉命名 = disembodied（脱体）；有身体反应 = embodied（具身）。

#### 3.4.1 身体反应关键词

```python
BODY_REACTION_KEYWORDS = {
    "手部": ["手", "指", "掌", "拳", "攥", "握", "捏", "松开", "收紧"],
    "面部": ["脸", "眉", "眼", "唇", "牙", "额", "偏头", "眯", "皱", "吞"],
    "躯体": ["肩", "背", "腰", "脚", "膝", "站", "蹲", "转身", "停"],
    "生理": ["呼吸", "心跳", "咳", "抖", "颤", "麻", "疼"],
}
```

#### 3.4.2 检测算法

```
1. 对每个高频名词的每次出现：
   a. 取所在段落
   b. 检查段落中是否包含身体反应关键词
   c. 标记为 embodied 或 disembodied

2. 统计：
   embodied_ratio = embodied出现次数 / 总出现次数

3. 判定：
   embodied_ratio ≥ 0.5 → 感知与身体关联良好
   embodied_ratio 0.25-0.5 → 部分关联
   embodied_ratio < 0.25 → 脱体严重（意象浮在叙述中，角色身体没有参与）
```

#### 3.4.3 评分公式

```
embodied_ratio ≥ 0.5 → 100
embodied_ratio 0.25-0.5 → 70
embodied_ratio < 0.25 → 40
```

### A5. 跨章意象演化（Cross-Chapter Evolution）

**检测目标**：同一意象跨章应演化——Ch1 视觉引入 → Ch2 声音/气味探索 → Ch3 触觉亲密。同通道重复 = 停滞。

#### 3.5.1 检测算法

```
输入：多章文本（至少2章）
输出：每个高频名词的跨章演化曲线

1. 对每章分别运行 A1（感知维度覆盖）
2. 对每个高频名词：
   a. Ch1: 通道分布 = {视觉: 0.9, 听觉: 0.1, ...}
   b. Ch2: 通道分布 = {视觉: 0.7, 听觉: 0.2, ...}
   c. Ch3: 通道分布 = {视觉: 0.5, 听觉: 0.2, 触觉: 0.3, ...}
3. 计算演化：
   - 通道多样性是否在增加（覆盖率是否在上升）
   - 是否有新通道在后续章节出现
   - 是否有通道在后续章节消失
```

#### 3.5.2 评分公式

```
对每个高频名词：
  覆盖率趋势 = 末章覆盖率 - 首章覆盖率

  趋势 > 0.15 → "演化良好"（不扣分）
  趋势 -0.05 ~ 0.15 → "基本持平"（扣5分）
  趋势 < -0.05 → "感知退化"（扣15分）

  新通道出现：每出现1个新通道 +5分（奖励）
  通道消失：每消失1个通道 -5分（惩罚）

A5 总分 = max(0, min(100, 100 - 总扣分 + 新通道奖励))
```

#### 3.5.3 输出示例

```json
{
  "noun": "口子",
  "chapters": [
    {"chapter": "Ch1", "coverage": 0.17, "channels": ["视觉", "触觉", "嗅觉"]},
    {"chapter": "Ch2", "coverage": 0.22, "channels": ["视觉", "触觉", "嗅觉", "听觉"]},
    {"chapter": "Ch3", "coverage": 0.19, "channels": ["视觉", "触觉", "嗅觉", "听觉"]}
  ],
  "trend": 0.02,
  "new_channels": ["听觉"],
  "lost_channels": [],
  "score": 95,
  "diagnosis": "覆盖率先升后降，但Ch2引入了听觉通道。整体演化基本持平，未退化。",
  "suggestion": "Ch3覆盖率(19%)低于Ch2(22%)，可以考虑在Ch3增加触觉或效应通道的描写。"
}
```

## 四、数据结构

### 4.1 主报告结构

```python
@dataclass
class PerceptionReport:
    file: str
    total_chars: int
    total_paragraphs: int

    # A1: 感知维度覆盖
    noun_coverage: List[NounCoverage]  # 每个高频名词的通道分布
    a1_score: float

    # A2: 替代词通道转移
    transfer_stats: List[TransferStat]  # 每个名词组的通道转移率
    a2_score: float

    # A3: 高频名词自发现
    discovered_nouns: List[DiscoveredNoun]  # 自动发现的名词分组
    a3_score: float  # 发现质量（是否有足够的变体分组）

    # A4: 感知-身体关联
    body_linkage: List[BodyLinkageStat]  # 每个高频名词的具身率
    a4_score: float

    # A5: 跨章演化（单章时为空）
    evolution: Optional[List[EvolutionStat]]
    a5_score: Optional[float]

    # 综合
    overall_score: float
    summary: str
```

### 4.2 核心数据结构

```python
@dataclass
class NounOccurrence:
    """单次出现记录"""
    para_idx: int        # 段落号
    word: str            # 具体使用的词（原词或变体）
    channel: str         # 感知通道（视觉/听觉/嗅觉/触觉/效应）
    context: str         # 上下文（前后20字）
    has_body_reaction: bool  # 是否有身体反应

@dataclass
class NounCoverage:
    """单个高频名词的感知维度覆盖"""
    noun: str                    # 名词组名（如"裂缝"）
    core_word: str               # 核心词
    variants: Dict[str, int]     # 变体及出现次数
    total_occurrences: int       # 总出现次数
    occurrences: List[NounOccurrence]  # 每次出现详情
    channel_distribution: Dict[str, ChannelStat]  # 通道分布
    coverage_ratio: float        # 非视觉覆盖率
    embodied_ratio: float        # 具身率
    score: float
    diagnosis: str
    suggestion: str

@dataclass
class ChannelStat:
    """单个通道的统计"""
    count: int
    ratio: float
    example_paras: List[int]     # 使用该通道的段落号

@dataclass
class TransferStat:
    """替代词通道转移统计"""
    noun: str                    # 名词组名
```

### 6.3 P2 金句密度修复方案

v2.0 的 P2 误判问题：

```
当前逻辑：
  if char_count <= 30 and para.count('"') == 0:
    if any(m in para for m in philosophical_markers):
      return True  # 判为金句

问题：philosophical_markers 包含 "安静" "什么都没" "像" 等过于宽泛的词
```

修复方案：

```python
# v3.0 修复：短句需要同时满足多个条件才判为金句
def detect_punchline_v3(para: str) -> Tuple[bool, str]:
    char_count = count_chars(para)

    # 条件1：长度限制（保留）
    if char_count > 50:
        return _detect_punchline_long(para)

    # 短句判定：需要同时满足 ≥2 个条件
    conditions = 0

    # 条件A：包含对比结构（不是A是B / 没有X只有Y）
    if re.search(r"(?:不是.*?是|没有.*?只有|不.*?倒是)", para):
        conditions += 1

    # 条件B：包含超验判断（比X更Y / 算得出X算不出Y）
    if re.search(r"(?:比.*?更|算得出.*?算不出|能.*?不能)", para):
        conditions += 1

    # 条件C：包含哲理性名词（规则/代价/选择/意义/重量）
    if any(w in para for w in ["规则", "代价", "选择", "意义", "重量", "重要"]):
        conditions += 1

    # 条件D：独立成段（前后有空行）且 ≤15字
    # （这个条件在段落级别自动满足）

    # 需要至少2个条件同时满足
    if conditions >= 2:
        return True, para.strip()[:60]

    # 单独的 "安静。" "程铖没动。" 不判为金句
    return False, ""
```

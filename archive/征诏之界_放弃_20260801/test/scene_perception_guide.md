# 场景感知写作法 — 动笔前操作手册

> 定位：替代 beat sheet 的"信息交付"思维。不是 lint 规则，不是配额——是动笔前的注意力方向。
> 来源：exp019 场景感知实验 + P001-P056 原则库 + S1-S18 技法维度
> 适用：chapter-writer 动笔前，替代 `purpose` + `info_delivery` 标注

---

## 一、为什么需要这个

当前 beat sheet 让写手按"信息交付"思维写作：

```
beat_id: 1 → purpose: "世界观展示" → info_delivery: "action"
写手思维：要交代世界观 → 写出动作包装的信息
```

真正作家按"场景感知"思维写作：

```
场景：城墙 → 角色在感知什么？ → 风在吹、光在暗、铜钱在转
写手思维：角色此刻感知到了什么 → 信息从感知中自然流出
```

**区别**：信息不是交付目标，是感知的副产物。

---

## 二、场景感知五问（替代 beat purpose + info_delivery）

写每个场景前，回答五个问题：

### Q1: 镜头在哪一层？

焦距决定读者从什么距离进入场景。

| 层级 | 示例 | 使用时机 |
|------|------|---------|
| 世界级 | "大徵在别的位面开了裂缝" | 章首/卷首/转场 |
| 城市级 | "城里的人不去看它" | 场景切换 |
| 建筑级 | "城墙上有一道裂缝" | 进入具体场景 |
| 人物级 | "程铖站在城墙上数人" | 角色登场 |
| 极近景·物件 | "铜钱背面有一道划痕" | 情感锚点 |
| 极近景·身体 | "手在发抖" | 情感爆发 |

**规则**：
- 章首从世界级或城市级开始（P048），不要直接跳到人物级
- 焦距可以推近（世界→人物→物件），但推近后必须拉回（P049）
- 一次极近景后，下一段拉回广角形成呼吸

### Q2: 角色的身体在干什么？

不是"要展示什么能力/性格"，是"此刻身体在做什么动作"。

**错误思维**："这个 beat 要展示程铖的精算能力"
**正确思维**："程铖的手在转铜钱，三枚在指缝间翻转"

身体动作的来源：
- 角色卡中的 `habits` / `personality_extreme` → 习惯性微动作
- 当前场景的物理需求 → 守城必须数人、磨刀必须蹲着
- 情绪的物理外化 → 不写"他很紧张"，写"手在发抖"

### Q3: 角色感知到什么？

至少 2 种感官叠加（P045-P047），且引入后必须萦绕（P045）。

| 感官 | 引入方式 | 萦绕方式 |
|------|---------|---------|
| 视觉 | 裂缝的暗紫色光 | 后续段落再次提及光的颜色变化 |
| 听觉 | 磨刀声"又碎又哑" | 后续段落磨刀声节奏变化 |
| 触觉 | 铜钱"金属擦过皮肤的凉" | 后续铜钱变烫/变黏 |
| 嗅觉 | "碱的，干的" | 后续气味越来越清晰或被新气味覆盖 |
| 温度 | "烫得像热油" | 后续手背蜕皮、温度残留 |

**感官自检**（P045）：
- 气味引入后，场景后半段还有没有它的痕迹？
- 温度有没有突变过？
- 感官之间有没有互触发关系（如看到光→闻到碱味）？

### Q4: 世界在干什么？

与角色无关的、世界自己的活动（P001-P004, S1）。

- 生物活动：苔在发亮、虫在啃石缝、白虫爬出
- 天气变化：风停了又起、天黑透了
- 物件自主变化：被子被吹走、铜钱朝向变了

**规则**：
- 每章至少 1 句世界自转——不推进剧情、不立人设、不埋伏笔
- 世界自转不与角色心情押韵（不是"风也在悲鸣"）
- 一句就够，不需要一段

### Q5: 这个感知改变了什么？

感知 → 反应 → 新感知的链条。场景之间的衔接靠感知链条，不靠信息跳转。

```
铜钱转出方向（感知） → 走向东墙（反应） → 看见裂缝在蠕动（新感知） → 压低声音"来了"（反应）
```

**错误衔接**："交代完世界观后，下一个 beat 是冲突展示"
**正确衔接**：角色的感知驱动他的行动，行动带来新感知，形成链条

| beat 间靠 purpose 衔接 | `perception_chain` 驱动衔接 |

## 四、意象预算（imagery_budget）

**问题**：v5 实验发现，关键意象（暗紫色、碱味、铜钱）出现频率远超读者承受阈值，且缺乏变体。评审意见指出"暗紫色出现19次"、"碱味出现18次"，读来重复。

**原理**：意象是氛围的骨架，但骨架重复读者会麻木。每章核心意象有预算上限，超出时必须用变体替代。

### 意象预算表

| 意象 | 每章上限 | 变体要求 | 变体示例 |
|------|---------|---------|---------|
| 暗紫色 | ≤8次 | 变体占比≥40% | 暗光、纹路、紫雾、暗色、深紫 |
| 碱味 | ≤6次 | 变体占比≥40% | 干涩、发紧、砂粒感、焦糊、干热 |
| 铜钱 | ≤15次 | 变体占比≥50% | 那枚、掌中之物、铜面、旧物、三枚 |
| 磨刀 | ≤6次 | 变体占比≥30% | 磨石声、刀刃声、砂粒碎裂 |
| 裂缝 | ≤10次 | 变体占比≥40% | 界门、口子、裂纹、石缝、城墙根 |

### 变体替换策略

```
原写：暗紫色的光从裂缝里渗出来（第3次用"暗紫色"）
→ 替换：纹路沿着石砖边缘蠕动，颜色像磕出来的淤伤

原写：碱味灌进喉咙（第4次用"碱味"）
→ 替换：干涩的气灌进喉咙，嗓子眼里那粒砂又大了

原写：铜钱在指间翻转（第10次用"铜钱"）
→ 替换：三枚在指缝间翻转 / 掌中之物没有声音
```

### 自检规则

- 写完后标记每个意象出现位置，超出预算的用变体替换
- 同一意象连续2段出现时，第二段必须换变体
- 一段内同一意象出现≥2次时，第二次必须用代称

## 五、段落功能分配（para_function_map）

**问题**：v5 实验发现，金句密度过高（Ch2达5.4/千字），哲理性收尾句连续出现，读者疲劳。评审意见指出"金句过多，像在背格言"。

**原理**：段落有功能分工。感官段建氛围，动作段推剧情，heavy段立金句，plain段做过渡。金句是重音，重音太多就不是重音了。

### 段落功能分类

| 功能 | 定义 | 占比目标 | 允许金句 |
|------|------|---------|---------|
| sensory | ≥2种感官叠加，建立氛围 | 15-25% | 否 |
| action | ≥3个动作动词，推进剧情 | 10-20% | 否 |
| dialogue | 含对话引号 | 30-45% | 对话内可含金句 |
| heavy | 短段+哲理性收尾 | ≤10% | 是（唯一金句位） |
| plain | 过渡/叙述/描写 | 15-30% | 否 |

### 金句预算

| 指标 | 上限 | 说明 |
|------|------|------|
| 每章金句数 | ≤6 | heavy段+对话内金句合计 |
| 每千字金句数 | ≤2.0 | 超过2.0/千字开始扣分 |
| 金句间距 | ≥5段 | 两个金句之间至少隔5个非金句段 |

### 功能分配流程

```
1. 写 scene_sheet 时，为每个段落标注功能
2. 统计功能分布，检查 heavy 段是否≤10%
3. 标记金句位置，检查间距是否≥5段
4. 写正文时严格按功能分配执行
5. 写完后运行 framework_experiment.py 验证
```

### 金句修剪策略

```
原写（heavy段+金句）：
  他攥住铜钱。攥得很紧。指节发白。
  铜钱比他重要。← 金句

→ 修剪为（sensory段，无金句）：
  他攥住铜钱。攥得很紧。指节发白，铜钱的边缘硌进掌心。
  掌心里那点凉早被体温捂没了。
```

**原则**：金句不是写出来的，是攒出来的。一章攒一句重的，胜过章章都是格言。

## 六、叙述者声音的边界

v4 诊断发现：叙述者声音是双刃剑。需要区分两种叙述者介入：

### 允许：叙述者评论

叙述者对世界/物件/规则发表态度，但不解释角色动作。

```
✅ "不掉色的墨配不上来的人，倒是配得上不回来的人。"
   → 叙述者对红印的讽刺，不解释任何角色动作

✅ "其实记得也没有用，名字不能让伤口不疼。"
   → 叙述者对"老疤"这个名字的点评，独立于角色
```

### 禁止：叙述者翻译

角色动作后紧跟解释，等于给哑剧递字幕。

```
❌ "手在发抖。脸很平静。" → "脸可以骗人，手不行。"
   → 动作已经说完了，叙述者又解释一遍（违反P051）

❌ "砍的时候没叫，砍完也没叫。" → "那不叫硬，那叫没有别的选择。"
   → 行为已经展示了"硬"，叙述者又翻译一遍
```

**判断标准**：删掉叙述者的话，角色动作自己能不能站住？
- 能站住 → 叙述者评论（保留）
- 站不住 → 叙述者翻译（删掉，补行为）

## 七、动笔流程（替代旧流程）

```
1. 读大纲，确定本章的感知方向（角色要从什么场景走到什么场景）
2. 写 scene_sheet：每个场景回答五问 + 填写 imagery_budget + para_function_map
3. 写正文：从焦距最高的层级起笔，逐层推近到角色身体
4. 写完后自检 S1-S18（见 craft_guide.md）
5. 运行 scene_perception_lint.py 诊断（D1-D7）
6. 运行 framework_experiment.py 验证意象预算和金句密度
7. 修复超预算意象（用变体替换）和过密金句（转为plain/sensory段）
8. 运行 style_lint.py（不变）
```

## 八、诊断脚本使用

```bash
# 单章诊断
python test/scene_perception_lint.py output/chapter_001.txt

# 输出 JSON 报告
python test/scene_perception_lint.py output/chapter_001.txt --json report.json

# 版本对比
python scene_perception_lint.py v4.txt --compare v5.txt

# 意象预算 + 金句密度验证
python test/framework_experiment.py output/chapter_001.txt
python test/framework_experiment.py output/chapter_001.txt --json report.json
```

### 评分解读

| 综合评分 | 说明 |
|---------|------|
| ≥80 | 场景感知良好，信息交付模式残留少 |
| 60-79 | 中等，存在信息交付段落或叙述者翻译 |
| <60 | 不足，信息交付模式主导，需重构 |

### 重点修复维度

- **D2 叙述者翻译**：删掉动作后的解释句，让行为自足（P051）
- **D4 感官一次性**：让引入的感官在后续段落萦绕（P045）
- **D1 信息交付段**：把背景交代拆散到感知中（P003）
- **D5 焦距起点**：章首从世界级广角开始（P048）

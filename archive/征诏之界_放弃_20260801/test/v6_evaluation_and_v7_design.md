## 二、三个致命问题

### 2.1 T1 完全失效（天花板）

**v6.0 T1 检测项及三章触发情况：**

| 检测项 | 触发条件 | Ch1 | Ch2 | Ch3 | 原因 |
|--------|----------|:---:|:---:|:---:|------|
| 信息交付段 | info≥4 且 body≤1 且 sensory≤1 且非对话 | 0 | 0 | 0 | 条件太严：几乎每段都含身体词或感官词 |
| 空间失锚 | 动作动词≥3 且锚点<0.5 且前文<0.5 | 0 | 0 | 0 | v7 重写版空间锚定已达标 |
| 焦距起点 | 首段无画面/人物级开篇 | 0 | 0 | 0 | v7 已是"画面级广角" |
| 专名锚定 | 专名首次出现无上下文 | 0 | 0 | 1 | 仅 Ch3 "征调者"未锚定 |

**根因**：v6.0 把 T1 从 v5.0 的"分类+梯度评分"简化为"只检测问题段"。但 v7 重写版已经解决了这些问题（场景感知写作法的成果），所以 T1 无问题可报 → 100分。

**这意味着 T1 无法区分"真正的好文本"和"还行的文本"——它只能检测"极差的文本"。**

### 2.2 T2 天花板未打破

**v6.0 T2 新增检测项及触发情况：**

| 检测项 | 模式示例 | Ch1 | Ch2 | Ch3 | 原因 |
|--------|----------|:---:|:---:|:---:|------|
| 动作后翻译 | 动作句→解释句 | 1 | 0 | 0 | 仅检测特定解释标记词 |
| 情绪直说 | "他感到恐惧" | 0 | 0 | 0 | **好文本不写"他感到恐惧"——模式永远不会触发** |
| 总结评论 | "就这样"/"这便是" | 0 | 0 | 0 | 同上——好文本不写这些 |
| 金句密度 | >3/千字 | 0 | 0 | 0 | 三章密度 1.4-2.0，未超限 |
| 世界自转 | 只统计不加分 | 10 | 11 | 10 | 统计值但不影响评分 |

**根因**：v6.0 新增的情绪直说和总结评论模式，本质上是在检测"差文本的特征模式"。但 v7 重写版已经是好文本——它不会写"他感到恐惧"，所以这些模式永远不会触发。

**T2 的天花板不是 bug，是设计缺陷：它只能检测"作者介入"，但好文本的定义就是"作者不介入"。所以好文本必然 100 分。**

### 2.3 框架退化为单维工具

```
木桶效应下的实际评分链：

T1 = 100 (A)  ← 恒定，不提供信息
T2 = 90-100 (A)  ← 近恒定，不提供信息
T3 = 52-80 (C-D-B)  ← 唯一变量

总评 = min(T1, T2, T3) = T3

→ 三维框架 = 一维工具
→ 80% 的代码（T1+T2 检测逻辑）在产出零价值
```

## 三、根因诊断

### 3.1 三轮迭代的规律

```
v4.0：正则做语义分析 → 检测不准（名词漏检、金句误报、自转虚高）
  ↓ 修复方式：加滑动窗口、加语义过滤、加主体性检测
v5.0：修了 5 个症状 → 暴露新症状（人名误报 73%、T2 天花板、T4 僵化）
  ↓ 修复方式：加白名单过滤、加情绪/总结检测、砍 T4
v6.0：修了 T3 误报 → T1/T2 天花板，框架退化为单维
  ↓ 修复方式：继续修？还是换思路？
```

**规律**：每次用正则修一个检测不准的问题，就会暴露新的"检测不准"问题。因为根本矛盾从未解决。

### 3.2 根本矛盾

```
正则擅长：计数（频率、位置、长度、距离）
正则不擅长：判断（这段是角色感知还是作者交代？这句话是金句还是叙述？）
```

v4-v6 每次迭代都在试图用正则做**判断**（分类段落、判定金句、识别叙述者介入），每次都失败。而 v6 唯一有效的 T3，做的是**计数**（统计意象词的通道分布）——这恰好是正则擅长的。

### 3.3 评分体系的原罪

评分需要可靠的检测。检测不可靠 → 评分不可靠。v6 改为木桶评级，但木桶效应只是让"最差的维度决定总评"——如果最差的维度恰好是唯一有效的维度（T3），木桶效应就让总评变成了 T3 的评级。

**评分本身不是目的。** 写手需要的是"哪里有问题、怎么改"，不是"85.2 分"。

## 四、v7.0 框架重设计

### 4.1 设计理念：从"评分器"到"画像器"

| | v4-v6（评分器） | v7.0（画像器） |
|---|---|---|
| **目标** | 给文本打分 | 描绘文本的感知特征分布 |
| **输出** | 分数 + 评级 + 问题清单 | 结构化画像（频率、分布、位置） |
| **判断者** | 脚本 | 写手 / LLM Agent |
| **正则角色** | 语义判断（不擅长） | 模式计数（擅长） |
| **与 SPL 关系** | 竞争（重叠检测） | 互补（SPL 做质检，v7 做画像） |

**核心理念**：工具不做最终判断，只如实描绘文本的感知特征。写手看画像，自己判断哪里需要改。

### 4.2 架构：一核两翼

```
perception_texture.py v7.0
│
├── 【核心】意象通道画像（继承 T3，大幅增强）
│   ├── 意象词白名单筛选（保留 v6.0）
│   ├── 20字窗口通道检测（保留 v6.0）
│   ├── 逐次出现画像（新增：每次出现的位置+上下文+通道）
│   ├── 全章通道热力图（新增：5通道在全章的分布密度）
│   └── 通道盲区检测（新增：哪些段落完全无感官信号）
│
├── 【左翼】节奏画像（替代 T1，做正则擅长的事）
│   ├── 段落长度分布 + 长短交替质量
│   ├── 句首词分布（主语重复检测）
│   └── 动作-描写-对话比例
│
└── 【右翼】重复画像（替代 T2，做正则擅长的事）
    ├── 精确短语重复检测（N字内重复≥2次）
    ├── 句式重复检测（相同结构在短距离内出现）
    └── 比喻密度 + 比喻类型分布
```

### 4.3 核心：意象通道画像（增强版 T3）

**保留 v6.0 的**：白名单意象词筛选、20字窗口通道检测、通道覆盖率计算

**新增能力：**

#### 4.3.1 逐次出现画像

不再只输出"'纹路'共6次，视觉通道占6次"。而是输出每一次出现的具体位置和上下文：

```json
{
  "word": "纹路",
  "total": 6,
  "channel_distribution": {"视觉": 6},
  "visual_only_ratio": 1.0,
  "occurrences": [
    {"para": 5, "context": "暗色的纹路沿着边缘蠕动", "channel": "视觉"},
    {"para": 12, "context": "壳和肉的交界处，纹路比别处薄", "channel": "视觉"},
    {"para": 18, "context": "他在脑子里已经量好距离", "channel": "视觉"},
    {"para": 25, "context": "黏在纹路里，擦不掉", "channel": "视觉"},
    {"para": 30, "context": "渗进纹路", "channel": "视觉"},
    {"para": 35, "context": "在纹路的第二个转折处", "channel": "视觉"}
  ],
  "suggestion": "第2次可加触觉（纹路硌手），第4次可加听觉（指甲刮过纹路的声音）"
}
```

写手看到这个画像，直接知道：第 12 段的"纹路比别处薄"可以改成"纹路比别处薄，指腹划过能感到一道棱"。**具体、可操作。**

#### 4.3.2 全章通道热力图

将全章按 10 段一组切片，统计每组的 5 通道（视觉/听觉/触觉/嗅觉/效应）信号密度：

```
段落 1-10:  视觉██████████ 听觉███ 触觉██ 嗅觉█ 效应████
段落 11-20: 视觉████████ 听觉████ 触觉███ 嗅觉██ 效应███
段落 21-30: 视觉███████ 听觉█ 触觉█ 嗅觉█ 效应██
段落 31-40: 视觉█████ 听觉██ 触觉█ 嗅觉███ 效应██
...
```

写手一眼看出：第 21-30 段听觉和触觉几乎为零——这段可能全是视觉描写，需要补充其他感官。

#### 4.3.3 通道盲区段落

标记"完全无感官信号"的段落（无视觉/听觉/触觉/嗅觉/效应关键词）：
- 这些段落可能是纯信息交付或纯对话
- 不是所有段落都需要感官——但连续 3 段无感官意味着场景丢失

### 4.4 左翼：节奏画像

**为什么用节奏替代 T1**：T1 试图判断"这段是角色感知还是作者交代"（语义判断，正则不擅长）。节奏画像只做"这段多长、前后段长短如何交替"（计数，正则擅长）。

**检测项：**

#### 4.4.1 段落长度分布

```
长度分布: [45, 120, 80, 15, 200, 60, 30, 150, 90, 25, ...]
交替质量: long-short-long-short → 良好
           long-long-long-short → 单调
           short-short-short-short → 碎片化
```

#### 4.4.2 句首词分布

统计每个句子的第一个词，检测主语重复：

```
句首分布: 他(12) 程铖(8) 老周(5) 铜钱(3) 风(3) ...
重复度: "他"占 24% → 可能主语单调
```

#### 4.4.3 内容比例

```
动作段: 35%  描写段: 40%  对话段: 25%
→ 比例合理
```

### 4.5 右翼：重复画像

**为什么用重复替代 T2**：T2 试图检测"叙述者介入"（语义判断，正则不擅长）。重复画像只做"这个短语在 N 字内出现了几次"（计数，正则擅长）。

**检测项：**

#### 4.5.1 精确短语重复

检测 3-8 字短语在 200 字内重复出现 ≥2 次：

```
"一收一放" 出现 4 次，最小间距 15 字 → 重复
"暗光" 出现 10 次，但最小间距 45 字 → 可接受
```

#### 4.5.2 句式重复

检测相同句式结构在短距离内重复：

```
"像...一样" 3次/500字
"X比Y更Z" 2次/500字
```

#### 4.5.3 比喻密度

```
比喻总数: 12
密度: 3.4/千字
类型分布: 明喻(8) 暗喻(3) 借喻(1)
→ 明喻占比过高，可增加暗喻
```

### 4.6 输出格式

**不再输出分数和评级。** 输出结构化画像 JSON：

```json
{
  "file": "chapter_001.txt",
  "total_chars": 3580,
  "imagery_profile": {
    "summary": {"total_imagery_words": 4, "avg_visual_ratio": 0.48},
    "words": [...],
    "chapter_heatmap": [...],
    "barren_paragraphs": [...]
  },
  "rhythm_profile": {
    "paragraph_lengths": [...],
    "alternation_quality": "good",
    "sentence_starters": {...},
    "content_ratio": {...}
  },
  "repetition_profile": {
    "repeated_phrases": [...],
    "pattern_repetition": [...],
    "metaphor_stats": {...}
  }
}
```

### 4.7 与现有工具的关系

```
写作质量检测生态（v7.0 后）
│
├── style_lint.py           ← 文风硬约束门禁（机械规则，L0阻断/L1顾问）
├── scene_perception_lint   ← 场景感知质检（D1-D7，段落级问题检测+评分）
├── framework_experiment    ← 框架层预防（意象预算+金句密度，写前规划）
│
└── perception_texture v7   ← 感知画像（新角色：不求分，只画图）
    ├── 意象通道画像（核心，继承T3）  ← 唯一独有价值
    ├── 节奏画像（新，正则擅长）      ← 补充 SPL 不覆盖的维度
    └── 重复画像（新，正则擅长）      ← 补充 framework_experiment 不覆盖的维度
```

**定位**：perception_texture v7 是 scene_perception_lint 的**补充**，不是替代。SPL 做"有没有问题"的判断，v7 做"问题长什么样"的描绘。

### 4.8 v6→v7 变更对照

| 维度 | v6.0 | v7.0 | 变更原因 |
|------|------|------|----------|
| T1 场景具身度 | 信息交付+空间失锚+焦距+专名（全与SPL重叠且不触发） | **删除** → 节奏画像（段落长度+句首词+内容比例） | T1与SPL重叠且天花板；节奏是正则擅长的新维度 |
| T2 叙述者介入 | 翻译+情绪直说+总结评论+金句（不触发或与SPL重叠） | **删除** → 重复画像（短语重复+句式重复+比喻密度） | T2天花板；重复检测是正则擅长的新维度 |
| T3 意象多样性 | 白名单筛选+20字窗口+通道覆盖（唯一有效维度） | **保留并增强** → 意象通道画像（+逐次出现+热力图+盲区） | T3是唯一独有价值，需增强而非替换 |
| 评分 | A/B/C/D 木桶评级 + 参考分 | **删除** → 纯画像输出，无评分 | 评分在所有版本都不可靠，画像不需要分数 |
| 输出 | 问题清单+建议 | **改为** 结构化画像JSON（频率/分布/位置） | 画像比问题清单信息量更大，且不做判断 |

## 六、实施计划

### 阶段 1：核心迁移（意象通道画像增强）
- 保留 v6.0 的 T3 核心逻辑（白名单+窗口+覆盖率）
- 新增逐次出现画像输出
- 新增全章通道热力图
- 新增通道盲区段落检测
- 删除 T1、T2 全部代码
- 删除评分系统

### 阶段 2：左翼开发（节奏画像）
- 段落长度分布 + 交替质量计算
- 句首词分布统计
